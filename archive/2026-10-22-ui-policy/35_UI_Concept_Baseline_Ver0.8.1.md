# 35. The Family — 승인된 UI 콘셉트 기준

**버전:** Ver0.8.1 · **작성일:** 2026-10-20  
**상태:** 화면군 콘셉트 사용자 승인 · 세부 치수·아트·실행 검수 별도  
**선택 조합:** H-2 / M-1 / D-1 / B-1  
**기준:** [UI 제작 지침](31_UI_Production_Guidelines_Ver0.8.1.md)

## 1. 적용 범위

세계와 인물을 먼저 보여주고, 필요한 순간에 필요한 정보와 조작을 제공한다. 기본 RPG의 마을·필드·대화·퀘스트·인카운터·아이템·장비·회복·저장을 우선 설계하며, 교역·운송·경영을 그 위에 연결한다.

| 화면군 | 채택 코드 | 적용 기준 |
|---|---|---|
| 마을·필드 | H-2 | 상황형 탐험 HUD |
| 메뉴·장비·일지 | M-1 | 작업 중심 목록·상세 |
| 대화·선택 | D-1 | 소형 양측 일러스트·단일 대사 |
| 최대 8인 전투 | B-1 | 하단 2열×4행 상태·고정 명령 영역 |

같은 역할의 부품·행동 슬롯·입력은 화면군에서 재사용한다. 이 승인은 콘셉트 선택이며 게임 규칙·전투 공식·경제 수치·최종 아트 또는 상용 품질 합격의 일괄 승인이 아니다.

## 2. H-2 — 상황형 탐험 HUD

| 정보 | 위치 원칙 | 표시 조건 |
|---|---|---|
| 지역 이름 | 좌상단 작은 영역 | 진입·지역 변경 때 표시한 뒤 축약 |
| 미니맵 | 우상단 | 공개된 지점만 표시, 사용자의 숨김 설정 보존 |
| 현재 추적 목표 | 미니맵 아래 고정 영역 | 한 퀘스트의 현재 행동 1~2줄, 접기와 다시 보기 제공 |
| 상호작용 | 선택 대상 근처 | 한 대상만 강조하고 실제 입력과 행동명을 표시 |
| 현재 파티 이상 | 하단 왼쪽 예약 영역 | 상태 변화 알림, 미해결 문제는 간략 표시로 유지 |
| 지도·메뉴 안내 | 하단 오른쪽 고정 힌트 | 큰 버튼 대신 작은 입력 안내 |
| 자금·달력·적재 | 관련 메뉴·이동 확인 | 돈·기간·수송 판단에 필요한 순간 표시 |

평상시에는 8명 전원의 초상·HP와 회사 장부를 펼치지 않는다. 미해결 위험은 단순한 타이머로 사라지지 않으며, 상태 상세로 다시 들어갈 수 있어야 한다. 목표를 추적하는 행위와 퀘스트 수락·실제 이동·진행 판정은 구분한다.

안전 마을, 좁은 실내, 갈림길 현장, 조사 대상 접근, 부상과 목표 갱신의 동시 발생에서 시야와 정보 우선순위를 검사한다. 공개되지 않은 단서·정체·정답 위치를 마커로 노출하지 않는다.

## 3. M-1 — 작업 중심 목록·상세

왼쪽 선택 목록, 오른쪽 상세·비교, 상단 문맥·탭, 하단 공통 행동 영역을 사용한다. 선택 중인 작업에 관계없는 전원 초상과 회사 통계는 표시하지 않는다.

| 작업 | 목록 | 상세·비교 | 주 행동 |
|---|---|---|---|
| 아이템 | 품목·수량·사용 가능 여부 | 효과·유효 대상·사용 전후 | 사용 또는 대상 선택 |
| 장비 | 슬롯·후보 | 현재 장비와 후보의 변화 | 장착 |
| 퀘스트 | 진행·완료 목록 | 현재 행동·확인된 단계·장소·보상 | 추적 또는 보고 위치 확인 |
| 일반 상점 | 상품·재고·가격 | 수량·총액·잔금·장비 비교 | 구매 또는 판매 |
| 기록 | 발견한 문서·읽은 대화 | 공개 본문과 출처 | 닫기 또는 관련 위치 |

공용 틀 안에서도 실제 목록·비교·대상 선택·결과가 있어야 한다. 기능 설명문만 바꾸는 화면은 완성된 조작 목업이 아니다.

큰 글씨에서는 필요할 때 목록과 상세를 단계별로 분리하는 접근성 변형을 사용한다. 기본안은 M-1이며, 상세 분리는 읽기 공간을 확보하는 재배치다. 헤더·행동 슬롯과 취소 후 선택·스크롤 복귀는 유지한다. 적용되는 확대 단계·치수는 실제 한글 배치 검토에서 정한다.

## 4. D-1 — 소형 양측 일러스트·단일 대사

하단 중앙 대사, 좌우 작은 흉상, 현재 화자 강조를 사용한다. 현재 발화는 한 본문에만 표시하고 상대의 이전 긴 대사를 나란히 남기지 않는다. 선택지는 고정된 선택 영역을 사용한다.

대사창·이름·일러스트·선택지·기록·입력 안내는 독립 부품이다. 인물과 문구는 승인 콘텐츠로 교체할 수 있어야 한다. 텍스트를 그림에 굽지 않으며, 얼굴과 본문·선택지가 겹치지 않게 한다.

`대화 → 제안 내용 확인 → 선택지 포커스 → 비용·중요 효과 확인 → 결정 → 후속 대화`

대사 넘김 입력이 새 선택창의 수락까지 이어지지 않게 한다. 긴 원문은 공용 상세창으로 한 단계 열고 대화로 복귀한다. 필수 대화의 취소가 임의 사건 중단으로 동작하지 않게 한다. 큰 전신·대형 초상 중심 연출은 기본안에 포함하지 않으며, 특별 장면의 예외는 별도로 검토한다.

## 5. B-1 — 하단 2열×4행 상태·고정 명령

전장 중앙을 확보하고 하단의 단순한 한 상태 영역에 최대 8명을 2열×4행으로 표시한다. 그 옆의 명령 영역은 위치를 고정하고 현재 단계의 내용만 교체한다. 8개의 대형 초상 카드와 장식 프레임으로 구성하지 않는다.

필수 정보는 이름·현재 HP·ATB·수동/자동·치명 상태다. 주요 인물과 용병을 첫 네 칸/나머지 네 칸으로 고정하지 않는다. 실제 편성 순서와 인물 ID를 유지하며 행동 준비 때마다 목록을 재정렬하지 않는다.

| 단계 | 유지 | 변화 |
|---|---|---|
| 전투 진행 | 전장·8인 상태·필수 목표 | 현재 행동명과 결과 |
| 명령 대기 | 같은 상태·같은 슬롯 | 해당 주요 인물의 명령 |
| 기술·도구 선택 | 같은 8인 상태 | 명령 영역의 목록·효과·비용 |
| 대상 선택 | 같은 8인 상태 | 유효 대상·범위·요약 |
| 실행 | 같은 8인 상태 | 목록을 접고 행동·효과 표시 |
| 결과 | 공용 결과 템플릿 | 승패·목표·소모·상태·보상·다음 행동 |

수동 명령 선택 중 적·용병·상태·목표의 전투 논리 시간은 함께 멈춘다. 운영 날짜는 메뉴나 전투를 읽는 현실 시간으로 진행하지 않는다. 고정된 턴 순서표·BP·브레이크를 장식으로 추가하지 않는다. 용병의 장비·레벨·경험치 또는 미승인 자원 게이지도 표시하지 않는다.

큰 글씨에서도 8명의 핵심 상태를 동시에 확인한다. 검수 구성은 1·4·6·8명, 주요 인물 1명+용병 7명을 포함한다. 정확한 명령창 방향·영역 크기와 하단 높이는 배치 검토 대상이다.

## 6. 공용 버튼·입력 기준

| 역할 | 상대 위치 | 적용 |
|---|---|---|
| 주 행동 | 하단 오른쪽 끝 | 사용·장착·수락·실행·계속 |
| 취소·이전 | 주 행동 바로 왼쪽 | 취소·이전·닫기 |
| 보조·도움말 | 하단 왼쪽 | 상세·보조 행동·짧은 문맥 안내 |
| 범주 전환 | 상단 고정 탭 영역 | 같은 입력으로 범주 이동 |

동일 템플릿·해상도·글씨 프로필에서는 크기·좌표를 고정한다. 주 행동이 없거나 불가여도 취소 버튼이 주 행동 자리를 차지하지 않는다. 본문은 스크롤해도 핵심 결과와 행동 영역은 고정한다.

일반 창과 소형 모달은 각각 자신의 경계를 기준으로 고정한다. 필드 행동 표식과 전투 명령 목록을 일반 창의 대형 버튼으로 강제하지 않으며, 각 용도의 공용 프로필을 사용한다. 한 번에 활성 입력 영역은 하나다.

## 7. 적용 단계와 검수 경계

승인 조합에 맞춰 기본 RPG 시스템의 진입·입력·판정·상태 변화·취소·실패·저장·복귀를 먼저 명세한다. 이후 장식 없는 배치와 공용 컴포넌트를 만들고 HTML 연결 동선, 아트 적용, 실제 Godot 검수 순으로 진행한다.

검증 동선: **마을 NPC → 대화·퀘스트 수락 → HUD 갱신 → 현장 이동·조사 → 전투 → 결과·목표 갱신 → 보고·보상 → 저장·재개**.

이 패키지는 제작 지침과 콘셉트 선택을 기록한다. 새 이미지·HTML·Godot 화면을 만들거나 검수한 산출물이 아니다. 본문의 픽셀 치수·최종 폰트·아트·게임 공식·신규 시나리오는 승인 범위에 포함하지 않는다.

## 8. 자료

공용 제작 원칙은 [31번](31_UI_Production_Guidelines_Ver0.8.1.md), 확인한 레퍼런스·세계관 근거와 한계는 [연구 근거](../reference/Research_Basis_Ver0.8.md), 선택값은 [정책 파일](../ui_policy_manifest.json)을 따른다. 문서 간 자동 기억이나 PC·저장소 자동 등록을 전제로 하지 않는다.
