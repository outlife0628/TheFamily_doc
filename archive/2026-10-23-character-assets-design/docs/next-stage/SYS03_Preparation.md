# SYS-03 캐릭터 시스템·UI — 작업 준비

문서 상태: RPG 핵심 디자인 검토 준비. 사용자 지시에 따라 스탯·레벨·성장·리소스 관리·테이블까지 이번 디자인에 포함한다. 캐릭터 시스템의 확정 명세나 구현 계획 승인본은 아니다. 현재 본문은 [캐릭터 시스템·UI 디자인](../character/03_Character_System_UI.md), 데이터 구조는 [테이블 부록](../character/Character_Data_Tables.md), 검토 선택은 [재검토 요청](../character/Character_Review_Request.md)을 따른다.

위 원문과 확정 결정이 설계 근거다. 정치 조력자/악역 전체 명단·각 Act의 합류/공개 시점은 콘텐츠 검토에 필요한 부분을 추가 확인한다. 모든 원문을 읽었다고 주장하지 않는다.

## 2. 그대로 유지할 기준

- 주요 인물과 용병을 구분한다. 일반/리더급 용병은 장비 교체·경험치·레벨업·훈련 성장이 없다. 용병 계약/유지비/손실 상세는SYS-07 소관이다.
- 공통 파티 최대8개·각8명. 상인 역할 인물도 정원에 포함하며 주요 인물은 분산 편성 가능하다. 인물 조회 선택은 파티 편성이나 실제 조작 전환이 아니다.
- 조회/목록 변경/닫기는 실제 위치·화물·자금·공통 날짜를 바꾸지 않는다. 메뉴를 읽는 현실 시간을 운영 날짜로 환산하지 않는다.
- 본작 이름·설정을 사용한다. 시안의 다른 게임 인물·레벨·문구를 복사하지 않는다.
- 1920×1080·글씨100% 단일·M-1 목록/상세·공용 행동 슬롯과 승인 재질을 재사용한다.
- 전체 캐릭터 원문에 있는 출생/관계/종장 정보가 모두 게임 시작부터 공개된 정보는 아니다. 공개 조건을 검토하기 전 숨겨진 설정을 UI에 표시하지 않는다.

## 3. 주요 인물의 원문 기준

아래는 서사 설정의 요약이다. 고정 직업·능력치·스킬 트리의 승인표가 아니다.

| 인물 | 원문에서 확인한 설정 | 기계 규칙으로 정하지 않은 것 |
|---|---|---|
| 크리스 | 인간, 실전 검술/무술, 균형형 전열, 일행의 의사결정 | 직업명·기본 스탯·검술 목록·보너스 |
| 브람 하르트 | 인간-드워프 혼혈, 기관/수리/제작/구조분석, 스팀 해머/방패·방어 성향 | 종족 수치 차이·탱킹 공식·제작 특전 |
| 엘리아나 베일 | 엘프, 활·회복·상태이상·원거리 지원, 자연환경 탐색 | 회복 자원·감지 수치·기술 비용·정체 공개 시점 |
| 올리버 크로포드 | 인간, 권총/도구, 상업·전술 보조, 거래/계약/운송 전문 | 정식 상인 자격 부여·흥정 보너스·전투 지원 공식 |

이동 목업의 `chris`·`bram`·`eliana`·`oliver` 식별자는 연결 참고로 보존한다. 이동 목업에서4명이 함께 나오는 것은 시험 편성이다. 정식 시작 파티나 전 인물의 합류 시점을 승인한 것으로 취급하지 않는다. 시험 코트/머리색·픽셀 스프라이트는 정식 캐릭터 아트 기준이 아니다.

## 4. 이번 디자인 검토 범위

이번 단위는 **캐릭터의 RPG 기반 시스템과 같은 기능의 UI**다. 정보 조회는 이 설계의 한 화면이며, 스탯·레벨·성장·리소스·관련 테이블을 이번 문서에서 함께 검토한다. 실제 전투·아이템·편성을 한 번에 구현하지 않는다.

| 포함할 검토 | 준비할 내용 | 이번에 실행하지 않는 것 |
|---|---|---|
| 인물 종류·역할 | 주요 인물/용병/리더급의 구분, 조회 대상과 자격 표시 | 영입·해산·파티 재편성 |
| 기본 정보·공개 범위 | 이름·알려진 배경·전문 분야와 미공개 설정 구분 | 새로운 정식 스토리·합류 시점 확정 |
| 스탯/계산 |6기본/11파생·기본/최종·보정 출처·산출/정수화·미리보기 | 시험 계수를 정식 밸런스로 확정 |
| 레벨/성장 | 개인XP·곡선표·상한·다중 레벨업·기술/랭크/패시브·중복 방지 | 용병 성장·미승인 보상 콘텐츠 실행 |
| 리소스 관리 | HP/SP 구성 비교·소유·보존·예약/소비·회복/HP0·상한 변경 | 미승인 회복품/휴식 가격·전투 효과 구현 |
| 테이블/저장 | PK/FK/형식/null·정의/상태·성장/비용·버전/복구·시험 행 | 새 DB/변환기/게임 저장 구현 |
| 같은 기능의 UI | 목록·상세·안내·닫기, 선택/스크롤/포커스 복귀 | 전체 주메뉴·장비 교체·전투 명령 |
| 미정/미지원 표현 | 계산할 근거가 없으면 미정/정보 없음으로 구분 | 미정 수치를0으로 넣거나 조작 가능한 버튼으로 위장 |

제안 동선은 인물 조회 진입 → 인물 선택 → 공개 정보/상태 의미 확인 → 이전 문맥 복귀다. 읽기 전용 화면에 실행할 주 행동이 없다면 해당 슬롯을 비워두며, 의미 없는 확인 버튼을 추가하지 않는다. 목록 조회만으로 조작 인물이나 파티를 바꾸지 않는다.

구체적인 권고 구조·처리 원칙·시험 수치는 연결된 디자인에서 검토 대기 상태다. 새 화면이나 게임 동작을 구현한 상태는 아니다.

## 5. 검토할 결정과 순서

| 순서 | 결정할 항목 | 확정 전의 처리 |
|---|---|---|
| 1 | 인물 유형·조회 대상·기본 공개 정보 | 주요4인 원문을 근거로 필요한 표시 항목부터 협의 |
| 2 | 능력치/상태 구성, HP·현재/상한·파생값의 의미 | HP/MP/SP·상태 목록·기본 수치 미확정. 표시/설명과 계산을 분리 |
| 3 | 주요 인물 성장·기술 습득 | 레벨/경험치·훈련·사건 등 방식을 협의. 용병 무성장 규칙 유지 |
| 4 | 관계/평판의 대상과 공개 | 개인 대 개인·인물 대 세력/지역을 구분. 공통 수치나 보너스 임의 도입 금지 |
| 5 | HP0·전투불능·사망의 연결 | SYS-05와 연계 협의. HP0을 즉시 영구 사망/게임오버로 해석하지 않음 |

성장 방식·능력치 목록·자원 구성·HP0 처리의 권고안은 이번 디자인에서 제시한다. 사용자 확정과 시험 수치를 구분한다. 관계 단위/등급과 후속 콘텐츠의 최종 수치는 별도 협의 항목이다.

## 7. 현재 산출물과 후속 작업

현재 디자인3개 파일을 작성했다. 후속 목업/구현 경로는 예정이며 아직 생성하지 않았다.

| 순서 | 예정 경로 | 내용/착수 조건 |
|---|---|---|
| 현재 | `docs/character/03_Character_System_UI.md` | 스탯·레벨·성장·자원·저장·같은 기능 UI/예외의 통합 디자인 초안 |
| 현재 | `docs/character/Character_Data_Tables.md` | PK/FK·형식·범위·성장/곡선/기술/비용·실행 상태·검토 예제 |
| 현재 | `docs/character/Character_Review_Request.md` | 사용자 요청 항목 대조·권고안/대안·수치와 구조 승인 구분 |
| 목업 계획 시 | `docs/character/Character_HTML_Acceptance.md` | 승인된 정책에 맞춰 실제 화면/입력 인수 조건 구체화 |
| 필요 시 | `art/ui_review/character-set-01/` | 승인 공용 에셋에 없는 초상/전용 부품만 별도 제안·검수. 정식 외형을 임의 생성하지 않음 |
| UI/규칙 검토 후 | `prototype/character-review/` | 승인 범위의 실제 HTML/CSS/JS. 기존 이동 소스는 보존 |
| 실행 단계 | `qa/character-review/` | 실제 실행한 검사·캡처와 미수행 항목을 분리 기록 |

단계별 진행은 규칙+UI 초안 → 필요한 선택 협의 → 추가 아트가 있다면 에셋 검수 → 승인 범위 HTML → 실제 실행/시각/지침 검수 → 사용자 검수다. 기존 공용 아트는 재사용한다. 설치·Godot 프로젝트·저장소 구성 변경은 현재 준비 범위에 없다.

## 8. 다음 기능의 검수 설계 항목

아래는 미래 인수 사례이며 전부 미실행이다. 현재 테스트 통과 수에 합산하지 않는다.

- 인물 선택/목록 재조회/닫기 후 자금·날짜·위치·화물·편성이 동일할 것.
- 긴 본명·8명 목록·미등록/비공개/결측 정보에서 잘림·스포일러·허위0값이 없을 것.
- 용병에 장비/레벨업/훈련 실행이 생기지 않을 것.
- 조회 대상과 실제 조작 인물을 혼동하지 않고 선택·스크롤·포커스가 복원될 것.
- 같은 역할의 행동 슬롯·320×64px·글씨100%·승인 에셋이 유지될 것.
- XP 경계·다중 레벨·상한·동일 결과 재시도에서 누락/중복 성장이 없을 것.
- 기술 비용·예약·취소·불가·회복·상한 변화에서 자원 복제/자동 소생이 없을 것.
- 성장/자원/습득 표의 PK/FK·누락·잘못된 유형·정의 버전 오류를 설명할 것.
- 정보 조회에 실제 실행 확인창을 붙이지 않고 추가 기능은 의미 있는 조건/사유와 함께 표시할 것.
- 새 HTML을 만들면 실제 화면과 키보드/포인터 검사를 별도로 실행·캡처할 것. 이동 목업의 과거 검사 결과를 새 화면에 재사용하지 않을 것.
