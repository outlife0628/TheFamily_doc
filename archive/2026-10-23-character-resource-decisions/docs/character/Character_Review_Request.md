# SYS-03 디자인 재검토 요청

상태: **성장 방식A 승인, 에셋 관리 보강안 재검토 대기**. 검토 대상은 [캐릭터 시스템·UI 디자인](03_Character_System_UI.md), [게임 수치/상태 테이블](Character_Data_Tables.md), [게임 에셋 관리 테이블](Character_Asset_Tables.md)이다.

## 승인된 성장 방식

개인 레벨+인물별 성장표+레벨/사건 기술 습득의 A형으로 진행한다. 성장 방식 자체를 다시 선택/승인 요청하지 않는다. 레벨 상한·XP 곡선/수령 범위·구체 초기값/기술 비용은 검토/시험 상태다.6스탯·HP/SP·회복/HP0 정책·에셋 설계까지 일괄 승인된 것으로 기록하지 않는다.

## 승인되지 않은 다른 설계 선택의 현재 상태

아래 항목은 현재 제안 상태를 유지한다. 이번 재검토의 주된 요청은 에셋 관리 보강안이며, 나머지가 자동으로 승인됐다는 뜻은 아니다.

| 선택 | 권고 기준안 | 다른 선택 시 영향 |
|---|---|---|
| 기본 스탯 | 체력·근력·기교·지성·의지·민첩6개 | 추가/통합하면 성장표·파생 계수·UI 항목 함께 조정 |
| 리소스 | HP+공통SP, 전투/필드 간 보존 | MP/직업별 자원 또는 전투 종료 충전을 원하면 기술/회복품/탐험 예산과 테이블 동시 검토 |
| 레벨업 회복 | 최대치만 증가, 현재HP/SP 유지 | 회복을 원하면 전량/증가분/비율·HP0 소생 여부를 명시하고 반복 회복 검수 추가 |
| HP0 | 생존 중 전투불능, 영구 사망은 별도 명시 결과 | 부상/사망 확률 등은 추가 규칙이며 기존 미정 사항을 별도 결정해야 함 |
| XP 수령 | 실제 참여한 생존 주요 인물 개인별 같은 양, 용병 성장 없음 | 대기/다른 파티 공유 성장을 원하면 중복/공통 시간·합류 레벨과 함께 검토 |
| 테이블 구조 | 정의/밸런스와 개체 상태 분리, 명시 레벨표, 영수증으로 중복 방지 | 기획자가 수치를 조정해도 현재 자원/XP를 초기화하지 않는 계약 필요 |

늦은 합류 기술 보정·동일 처리의 연쇄 습득·XP 수령 정책 등 성장 세부안과 공통 공개 영수증 계약은 문서의 제안 상태를 유지한다. A형이라는 성장 구조를 다시 선택시키는 항목으로 취급하지 않는다.

## 에셋 보강안에서 검토할 기준

- 파일 경로 대신 안정ID·불변 리비전·용도별FK로 인물과 아트를 연결한다.
- 필드 몸체·메뉴 아이콘은 필수 연결을 검사하고 초상/그림자는 문맥별 선택 항목으로 둔다. 몸체 누락은 준비 완료로 넘기지 않고 아이콘의 런타임 읽기 실패는 이름 텍스트와 오류 기록을 유지한다.
- 방향/동작을 데이터로 명시한다. 무기/외형의 좌우 반전은 기본 금지이며 명시 승인된 클립만 미러링한다.4/8방향·원화 크기는 최종 사양으로 고정하지 않는다.
- 여러 인물/프레임이 같은 파일을 공유해도1회 로드하며 화면별 참조를 해제한다. 파일/캐시 오류가HP/SP/XP·실제 위치를 바꾸지 않게 한다.
- 실제 아트·엔진 출력이 없는 fixture는 메타데이터/산술 검사용이며 납품/승인/실행 통과로 보고하지 않는다.

## 수치 승인과 분리할 항목

상한50·6기본 스탯의 범위·파생 계수·인물별 시작값/증가값·상한5의 시험XP 곡선·기술A/B·SP 비용은 전부 검토/시험값이다. 구조를 검토하더라도 정식 초기 레벨·4인 시작 파티·초기 기술·경제 수치·최종 밸런스까지 자동 확정하지 않는다.

실제 적/사건XP량·최종 피해/명중/ATB·회복품/휴식 조건·정식 상인 자격 인물·관계/평판 등급/보너스는 각 소유 문서와 남은 협의 항목을 구분했다. 캐릭터의 스탯/레벨/성장/자원 처리 설계를 그 이후로 미룬다는 뜻이 아니다.

## 검토 요청

에셋 관리 테이블·인물/용도 연결·프레임/방향·로딩/저장/실패 정책에서 수정할 항목을 확인해 달라. 성장 방식A는 승인대로 유지한다. 현재 산출물은 문서와 합성 메타데이터 사례이며 실제 스프라이트/아이콘 제작·새HTML·Godot 구현은 착수하지 않았다.
