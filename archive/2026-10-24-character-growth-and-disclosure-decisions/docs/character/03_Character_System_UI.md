# SYS-03 — 캐릭터 시스템·UI 디자인

**문서 상태:** 검토 초안 Ver0.7 · 성장/자원·8방향/반전·초상/아이콘 재사용·기본 외형/표시 영역 승인. 수치/에셋 등 나머지 항목은 순차 검토 중.  
**범위:** 캐릭터 스탯·레벨·경험치·성장·기술 습득·HP/SP 리소스·스프라이트/아이콘/애니메이션 에셋·데이터 테이블·저장 상태·관련 UI와 예외.  
**적용:** [현재 확정 결정](../../CURRENT_DECISIONS.md), 승인된 [공용 UI](../movement-assets-v2/UI_Production_Guidelines.md).  
**연결:** [게임 수치/상태 테이블](Character_Data_Tables.md) · [게임 에셋 관리 테이블](Character_Asset_Tables.md) · [검토 요청](Character_Review_Request.md).

이 문서에서 **승인/유지**는 사용자 결정, **제안**은 검토할 설계, **시험값**은 계산 정합성을 확인하는 예시다. 승인된 규칙은 §2와 §6~8을 따른다. 구체 성장 곡선·인물별 시작값·계수/수치·에셋 테이블의 세부까지 일괄 승인된 것은 아니다. 승인 근거는 [핵심 결정](../../qa/approvals/character-core-decisions-2026-10-23.json)·[XP/초기 레벨](../../qa/approvals/character-xp-decisions-2026-10-23.json)·[초기 기술/자원](../../qa/approvals/character-initial-and-resource-decisions-2026-10-24.json)로 구분한다.

## 1. 목적과 설계 경계

플레이어가 인물의 강점과 현재 상태를 이해하고, 성장 결과와 사용할 기술, 다음 전투·탐험에 남겨둘 리소스를 판단할 수 있게 한다. 같은 인물의 능력·진행·현재 자원이 화면이나 파티마다 따로 존재하지 않게 한다. 게임 제작자는 Excel 표에서 레벨/성장/기술/비용을 조정하고 오류 위치를 확인할 수 있어야 한다.

| 이번 문서에서 설계 | 연계 문서에 남기는 실제 기능 |
|---|---|
| 기본/파생 스탯 의미와 산출 순서, 보정 출처 | 장비 슬롯/장착 조건/개체 소비SYS-04, 피해·명중·ATB 계산SYS-05 |
| 개인 레벨·XP·상한·다중 레벨업·기술 습득·성장 결과 | 적별 XP 보상량·퀘스트별 보상 콘텐츠SYS-05/10 |
| HP/기술 자원의 소유·상한·소비/회복·취소·중복 방지 | 회복약·숙박/시간/가격SYS-04/11/14, 기술의 실제 효과SYS-05 |
| 인물/용병 차이, 역할 참조, 관계/평판의 데이터 경계 | 파티 편성SYS-06, 용병 계약SYS-07, 흥정/경제SYS-08 |
| 정의 테이블/실행 상태/공개 상태·저장할 값과 검수 | 실제 저장 파일·슬롯·마이그레이션 구현SYS-16 |
| 캐릭터 스프라이트/아이콘/초상·영역/프레임·애니메이션·용도 연결·로딩/해제 | 실제 이미지 제작·엔진 임포트·Map Tool 카메라/앵커 바인딩·전투 리소스 납품 |

미정인 적 보상량이나 휴식 가격이 없어도 캐릭터의 수치 의미·변경 원칙·입출력 계약은 이번에 검토한다. 후속 문서에 맡기는 것은 호출 주체/콘텐츠/전투 적용이지 캐릭터 기본 설계 자체가 아니다. HTML·Godot·Map Tool·새 캐릭터 이미지 제작은 이 문서 작업에 포함하지 않는다.

## 2. 유지할 규칙

- **유지:** 최대8개 공통 파티, 각8명. 주요 인물 분산 편성 가능. 상인 역할 인물도 정원에 포함한다.
- **유지:** 일반/리더급 용병은 장비 교체·경험치·레벨업·훈련 성장이 없다. 전투 자원·일시 상태를 가진다는 것과 성장하는 것은 다르다.
- **유지:** 조회·선택·미리보기·취소는 실제 조작 인물/파티·위치·자금·화물·공통 날짜를 바꾸지 않는다.
- **유지:** 메뉴를 읽는 현실 시간으로 날짜를 진행하지 않는다. 수동 명령 선택 중 전투의 적/용병/상태/목표 논리 시간이 함께 정지한다.
- **유지:** HP0을 곧바로 영구 사망·크리스 사망 게임오버로 판정하지 않는다. 사망/결정적 시나리오 실패의 별도 종료 가능성은 유지한다.
- **유지:** 본작 인물과 서사 설정을 사용한다. 이동 목업의4인 편성·시험 스프라이트·운임·기간은 정식 캐릭터 시작 조건이 아니다.
- **유지:** 1920×1080·게임 내 글씨100% 단일, M-1 목록/상세와 승인 에셋·공용 행동 슬롯을 사용한다.
- **승인:** 성장 방식A — 주요 인물 개인 레벨·인물별 성장표·레벨/사건 조건의 기술 습득. 자유 스탯/스킬 포인트 배분이나 반복 숙련/훈련 방식으로 변경하지 않는다.
- **승인:** 체력·근력·기교·지성·의지·민첩의6기본 스탯과 역할, 전투 인물의HP+SP 구성. 계수/수치는 별도 조정한다.
- **승인:** 전투 종료 후 HP/SP는 남은 수치 유지. 실제 레벨 상승 시에는 새 최대HP/SP까지 전량 회복한다.
- **승인:** HP0인전투불능인물은전투승리XP를획득하지않는다. HP0상태의레벨업은발생하지않으며,부활아이템또는부활가능장소에서부활한뒤활동한다.
- **승인:** 전투 XP는 실제 참가하고 승리 시 활동 가능한 주요 인물에게 개인별 고정량으로 지급한다. 대기·비참가·다른 파티 인물은 해당 전투 XP를 받지 않고, 제외자 몫을 다른 수령자에게 재분배하지 않는다.
- **승인:** XP는 캐릭터의 공통 성장 변수다. 전투·퀘스트·이벤트·XP 아이템을 포함해 어떤 시스템도 명시된 효과로 XP를 제공할 수 있다. 제공 시스템의 허용 목록으로 제한하지 않는다.
- **승인:** 전투불능 인물에게는 부활 아이템을 제외한 모든 아이템을 사용할 수 없다. XP·일반 회복·성장 아이템도 포함하며, 불가한 사용으로 물품을 소비하지 않는다.
- **승인:** 레벨 상한은100이다. Lv100에서도 추가 XP를 누적·저장하고 레벨은100을 유지한다.
- **승인:** 최초 합류 레벨은 파티 평균과 관계없이 캐릭터별 지정값을 적용한다. 재합류 시에는 기존 레벨/XP를 유지한다. 인물별 실제 지정 수치는 별도 밸런스 대상이다.
- **승인:** 전투 외 XP도 지급 시 HP0인 인물은 수령 대상에서 제외한다. 최초 합류 기술/랭크는 테이블 초기값 그대로 적용하고 이전 레벨/사건에 따른 자동 추가 습득을 하지 않는다.
- **승인:** 레벨업 외 최대HP/SP 증가는 현재량 유지, 감소는 새 최대치까지만 제한한다. SP 비용은 실행 시작 시 차감하며 실행 전 취소는 무소모, 실행 후 빗나감/저항은 환불하지 않는다.
- **승인:** 부활 후 HP/SP에는 부활 아이템·장소별 테이블의 회복 규칙을 적용한다. 실제 회복 수치·장소 가격/시간은 별도 콘텐츠다.
- **승인:** 필드 스프라이트는8방향으로 표시한다. 정면/후면과 좌우·앞 대각선·뒤 대각선 각 쌍의 한쪽을 원본으로 제작하고 반대쪽3방향은 좌우 반전한다. 정보 화면의 초상은 별도 전용 일러스트다.
- **승인:** 얼굴 아이콘은 전용 초상의 지정 얼굴 영역을 재사용한다. 장비 교체 시 필드 스프라이트와 초상은 기본 외형을 유지한다. 초상 UI 표시 영역은1920×1080 기준320×400px이며 구도는 아트 디자이너가 정한다.
- **유지:** 인물은3D 맵의2D 픽셀 스프라이트다. 에셋을 바꿔도 실제 인물ID·성장·자원·파티·위치를 바꾸지 않는다.

## 3. 승인된 성장 방식A

주요 인물은 개인 레벨·인물별 성장표로 기본 능력이 성장하고, 기술은 명시된 레벨/사건 조건으로 습득한다. 주요 인물의 기본 성장은 자동 적용하며 기술 활용·장비·편성을 선택의 축으로 남긴다. 별도 자유 스탯/스킬 포인트·사용 횟수 숙련·유료 훈련을 추가하지 않는다.

성장 방식·6기본 스탯·레벨 상한을 다시 선택시키지 않는다. 레벨 상한100·전투 XP 수령/분배·초기 레벨 지정·테이블 초기 기술 적용은 승인 기준이다. XP 곡선·기술별 수치·인물별 실제 초기값·합류 이후 기술 연쇄 처리의 세부안은 검토/시험 상태를 유지한다. 성장 방식 승인과 최종 밸런스·나머지 정책의 승인을 분리한다.

## 4. 인물 종류·정의·실행 상태

| 종류 | 스탯/자원 | 레벨/경험치/성장 | 기술/역할 | UI |
|---|---|---|---|---|
| 주요 인물 | 레벨 성장표와 현재 HP/SP | 개인별 레벨/인물별 성장표 **승인**, 지급/수치 세부 검토 | 레벨/사건별 습득 방식 **승인**, 세부 규칙/역할 목록은 검토 | 레벨·다음 성장·기술·자원 표시 |
| 일반/리더급 용병 | 고정 스탯표와 현재 자원 **제안** | 성장 없음 **유지**. 레벨/XP 상태 행을 만들지 않음 | 고정 기술 구성 **제안**. 리더 조건/계약은SYS-06/07 | `성장 없음` 표시. Lv1로 위장하지 않음 |
| 비전투 NPC/직원 | 필요한 공개 인물 정보 | 기본안에서는 전투 스탯/진행 없음 | 서사 전문 분야와 상인 자격은 별개 | 없는 값은 `해당 없음` |

`CharacterDefinition`은 인물/용병 템플릿의 정의이고, `ActorInstance`는 실제 상태 소유자다. 주요 인물은 같은 정의로 여러 실행 개체를 복제하지 않는다. 용병 템플릿은 서로 다른 개체ID를 가질 수 있다. 파티가 바뀌어도 개체ID·XP·현재 자원·습득 기술·영구 보정은 유지한다. 같은 주요 인물의 재합류는 최초 생성/전량 회복을 다시 실행하지 않는다.

원문 [주요 인물](../../reference/scenario/02_캐릭터_상세시트_주요인물.md)의 크리스(균형형 전열), 브람(기계/방어), 엘리아나(원거리/회복/탐색), 올리버(상업/전술 보조)를 성장 성향 참고로 사용한다. 종족으로 자동 보너스를 부여하거나 올리버의 서사적 상업 전문성을 확정 상인 자격/흥정률로 바꾸지 않는다. 원작의 직원 훈련 서술을 용병 성장으로 가져오지 않는다.

## 5. 캐릭터 스탯

### 5.1 기본 스탯 — 종류와 역할 승인

| ID | 표시명 | 의미/주요 연결 | 의미하지 않는 것 |
|---|---|---|---|
| `vitality` | 체력 | 최대HP·방어 기반 | 현재HP 자체 |
| `strength` | 근력 | 근접 위력·HP 일부 | 차량 적재량·파티 정원 |
| `dexterity` | 기교 | 원거리 위력·명중/치명 기반 | 상인 자격·거래 자동 성공 |
| `intellect` | 지성 | 기술/회복 위력·최대SP 기반 | 마법 체계/정식 MP 채택 |
| `willpower` | 의지 | 기술 방어·최대SP 기반 | 관계/평판 값 |
| `agility` | 민첩 | 행동속도·회피 기반 | 필드 이동속도·시간 소비의 자동 변경 |

기본 스탯은 프로필의 현재 레벨 값을 읽는다. 같은 레벨이라도 인물별 표가 다르다. 용병은 고정 표를 읽는다. 각 보정 출처와 기본/최종값을 따로 보여준다.

### 5.2 파생 스탯 — 검토용 산식 제안

아래 계수·범위는 **시험값**이며 정식 밸런스가 아니다. `V/S/D/I/W/A`는 보정·정수화가 끝난 기본 스탯이다.

| ID | 표시명 | 시험 산식 | 사용 계약 |
|---|---|---|---|
| `max_hp` | 최대HP | `80 + 12V + 4S` | 현재HP의 상한 |
| `max_sp` | 최대SP | `20 + 3I + 2W` | 현재SP의 상한 |
| `melee_power` | 근접 위력 | `2S + D` | SYS-05의 기술/피해 입력 |
| `ranged_power` | 원거리 위력 | `2D + S` | SYS-05의 원거리 기술 입력 |
| `tech_power` | 기술 위력 | `2I + W` | 기술/회복 효과 입력. 최종 회복량 자체가 아님 |
| `physical_guard` | 물리 방어 | `2V + W` | SYS-05의 물리 피해 계산 입력 |
| `tech_guard` | 기술 방어 | `2W + V` | SYS-05의 기술 피해 계산 입력 |
| `accuracy_score` | 명중 성능 | `2D + A` | 상대 회피·기술 조건과 함께SYS-05에서 적용 |
| `evasion_score` | 회피 성능 | `2A + D` | 실제 회피 확률이 아님 |
| `critical_score` | 치명 성능 | `D + W` | 실제 치명 확률이 아님 |
| `action_speed` | 행동속도 | `100 + 2A` | ATB 산식의 입력. ATB 게이지/단위 자체가 아님 |

명중·회피·치명을 확률처럼 `%`로 표시하지 않는다. 확률·내성·속성·상태 성공률의 최종 변환은SYS-05와 협의할 연결 항목이며, 캐릭터 화면에서 임의 확률을 계산하지 않는다. 저항 정의는 연계할 수 있도록 데이터 참조만 예약하고 새 속성 목록/면역을 이번에 만들지 않는다.

### 5.3 보정·계산 순서 — 제안

1. 성장표 또는 고정표에서 기본 스탯을 읽는다.
2. 영구 성장/장비/습득 패시브/유효 상태의 보정을 출처ID로 모은다. 조건·중첩은 각 소유 시스템이 해석한 유효 보정만 받는다.
3. 기본 스탯마다 `P = clamp(floor((B + Σflat) × max(0,10000 + Σrate_bps) / 10000), min, max)`를 적용한다.
4. 위 표로 파생 기본값 `D0`를 계산한다. 파생 스탯 자체를 대상으로 한 보정에는 같은 식의 `B=D0`를 적용한다.
5. 새 최대HP/SP를 확정한 **실제 변경**에서만 현재 자원을 보정한다. 조회/장비 미리보기는 현재 자원을 변경하지 않는다.

`10000bp=100%`, `+1000bp=+10%`다. 같은 단계의 비율 보정은 합산한다. 기본 스탯 단계와 파생 스탯 단계에서 각각 한 번 내림한다. 매 프레임 최종값에 보정을 다시 더하지 않고 정의/출처로 재계산한다. 같은 보정 개체ID를 중복 입력하면 거절한다. 서로 다른 보정을 기본/파생 양쪽에 의도적으로 부여하는 것은 기획 데이터에 명시해야 한다.

**시험 범위:** 기본 스탯1~999, 최대HP1~99999, 최대SP0~9999, 위력/방어/명중/회피/치명0~99999, 행동속도1~999. 이 상한도 밸런스 검토 대상이며 숫자 자릿수와 오버플로 검증의 기준으로만 사용한다. 음수/비정상 수치·미등록 스탯·순환 파생식은 오류다. 미정값을0으로 보정하지 않는다.

## 6. 레벨·경험치

### 6.1 승인된 레벨·누적 XP 구조

- **승인 구조:** 주요 인물은 개인별 레벨·인물별 성장표를 사용하며 파티 공통 레벨을 만들지 않는다. 정식 레벨 범위는1~100이다. 예제 데이터의 상한5는 경계 검사용 축소값이다.
- **승인:** 최초 합류는 `CharacterDefinition.initial_level`의 캐릭터별 지정값을 적용하며 파티 평균에 맞춰 조정하지 않는다. 재합류는 기존 레벨/XP를 유지한다. 실제 초기 레벨 값·곡선 속도는 별도 밸런스 검토 대상이다.
- `LevelCurvePoint`에 `level, cumulative_xp`를 정수로 명시한다. 레벨1의 누적XP는0이며 이후 엄격히 증가한다. 런타임은 표를 읽고 다음 조건의 최대L을 계산한다: `cumulative_xp[L] ≤ total_xp`.
- 저장 원본은 누적XP다. `level`·현재 레벨 내XP·다음 필요XP는 파생값이다. 저장 캐시가 있으면 재계산 값과 대조한다.
- **승인:** Lv100에서도 획득 XP를 계속 누적·저장한다. 누적값을 Lv100 기준 XP로 잘라내지 않으며, 레벨은 곡선 상한100까지 계산한다. 이미 MAX인 상태의 XP 획득은 레벨업 회복을 일으키지 않는다.
- 최대 레벨에서는 총 누적 XP와 `MAX`·`다음 성장 없음`을 표시한다. 가짜 다음 레벨/분모나 넘치는 진행 막대를 만들지 않는다. 큰 누적 XP를 정밀도 손실 없이 보존할 저장/표시 형식은 테이블 부록에서 검토한다.

### 6.2 XP 제공·전투 수령 규칙과 공통 처리

**승인:** XP는 특정 시스템에 종속되지 않는 캐릭터의 공통 성장 변수다. 전투·퀘스트·이벤트·XP 아이템을 포함한 모든 시스템이 명시된 효과로 XP를 제공할 수 있다. 출처 종류를 허용/금지 목록으로 고정하지 않는다. 보행·거래 등도 해당 시스템에서 XP 효과를 정의할 수 있으며, 이 문서만으로 새로운 자동 지급 규칙이나 보상량을 만들지는 않는다.

**공통 처리 제안:** 제공 주체는 확정 결과ID·실제 수령 개체ID 목록·개인별 XP량·출처 참조를 전달한다. 출처 참조는 기록/검증용이며 허용 시스템 목록이 아니다. 동일 결과를 여러 화면에서 열어도 다시 지급하지 않는다. `(operation_id, actor_id)`가 같은 요청의 내용도 같으면 기존 결과를 반환하고, 내용이 다르면 충돌로 거절한다.

**승인:** 지급 시 HP0인 인물은 전투·퀘스트·이벤트 등 모든 XP의 수령 대상에서 제외한다. 부활 아이템 외 아이템도 HP0에게 사용할 수 없다. 뒤에 부활해도 제외된 전투 XP를 지연 지급/재수령하지 않으며, HP0 인물이 레벨업 회복으로 부활하는 경로를 만들지 않는다. XP 제공 시스템의 종류를 제한하는 것과 개체의 수령 조건을 구분한다.

**승인:** 실제 전투에 참여해 승리 시 활동 가능한 주요 인물에게 개인별 고정량을 지급한다. 보상이100 XP라면 각 유효 수령자가100씩 받는다. 총량을 나누지 않으며 HP0 등 제외자 몫을 다른 사람에게 더하지 않는다. 대기·비참가·다른 파티 인물은 해당 전투 XP를 받지 않는다. 다른 파티는 자신이 수행한 전투/활동에서 별도로 받을 수 있다. 용병·NPC는 기존 무성장 규칙을 유지한다.

전투 참가 조건은 전투 XP에만 적용하며 퀘스트·아이템 등 다른 XP에 그대로 강제하지 않는다. 직접 전투와 비선택 파티 자동전투는 같은 전투 수령 규칙을 사용한다. 실제 적별량·도주/참여 판정·각 시스템의 지급 조건/콘텐츠는 소유 문서와 협의한다. **현재 지급 계약 제안:** 음수/소수 XP·미등록 수령자·중복 수령자는 거절하고0은 변화 없는 처리로 기록한다. XP 소비·차감·레벨 하락은 이번 제공 경로 승인에 포함하지 않는다.

### 6.3 레벨업 처리 순서 — 제안

결과 유효성/중복 검사 → HP0 수령 제외·제공 효과별 대상 조건 검사(전투는 실제 참가/승리 시 활동 가능, 아이템은 사용 대상 제한) → 누적 XP 전량 적용 → 곡선 상한까지 오른 모든 레벨 산출 → 새 성장표/기술 습득 → 보정/파생 스탯 재계산 → 실제 레벨 상승자의 HP/SP를 새 최대치로 회복 → XP/습득/자원/처리 영수증을 함께 확정한다. 실패하면 전체 변경을 취소한다. 제외된 인물 때문에 다른 유효 수령자의 지급을 막지 않으며, 미등록 개체/손상 데이터는 별도 오류로 처리한다.

한 번에 여러 레벨이 올라도 중간 레벨 기술을 빠뜨리지 않는다. **제안:** 같은 처리 안에서 새 기술로 선행 조건이 충족되면 종속 기술도 즉시 평가한다. 기술 조건은 현재 레벨·영구 사건 사실의 고정 스냅샷·명시된 선행 기술만 참조하며, 스탯/HP/다시 계산되는 임시 상태를 해금 조건으로 삼지 않는다. 조건이 맞는 랭크를 적용하고 더 이상 바뀌지 않을 때까지 반복한다. 선행 그래프는 순환을 금지하고, 같은 결과의 순서를 규칙ID로 고정한다. 이미 얻은 랭크를 중복 보상하거나 낮추지 않는다. 상한에서 새 조건이 충족돼도 추가 레벨업 없이 해당 처리에서 연쇄 습득한다. 아직 충족하지 못한 조건은 다음 관련 사실 변화에서 재평가한다.

**최초 합류 승인:** 캐릭터별 초기 레벨과 초기 기술/랭크는 테이블의 지정값을 그대로 적용한다. 초기 레벨 이하의 습득 규칙이나 과거 사건 사실을 소급 평가해 초기 기술을 추가하지 않는다. 초기 기술에 연결된 패시브를 반영해 최종 상한을 계산한 뒤 최초 자원 정책을 한 번 적용한다. 초기 테이블에서 빠진 기술을 추정해 보충하거나 과거 XP/물품/자금 보상을 재지급하지 않는다. 재합류는 기존 개체의 XP/기술/자원을 복원하며 초기 테이블을 덮어쓰지 않는다. 합류 이후의 실제 레벨/사건 변화는 성장 규칙의 별도 처리다.

**승인:** 실제 레벨이 오르면 최종 스탯/패시브까지 재계산한 새 최대HP/SP로 모두 회복한다. 여러 레벨이 한 번에 올라도 최종 최대치로 한 번 처리한다. XP만 받고 레벨이 오르지 않거나 이미 MAX이면 레벨업 회복을 발생시키지 않는다. HP0의 전투 승리 XP 제외·일반 아이템 사용 불가를 지키며 레벨업 소생 우회를 만들지 않는다. UI는 스탯 증가·기술 습득·전량 회복을 함께 알리고 결과를 다시 열어도 회복을 재적용하지 않는다.

## 7. 성장 요소·기술 습득

| 성장 축 | 제안하는 데이터/결과 | 적용 경계 |
|---|---|---|
| 개인 레벨 성장 | 인물별 레벨/스탯 표에서 기본 스탯 변경 | 파티 이동/게임 날짜로 자동 성장하지 않음 |
| 기술/기술 랭크 | 지정 레벨 또는 승인 사건 조건으로 자동 습득/상향 | 별도 스킬 포인트나 사용 반복 숙련은 기본안에 없음 |
| 고유 패시브 | 명시된 습득 규칙·보정 정의를 통해 적용 | 기술 재열람으로 재적용 금지. 종족만으로 자동 신규 패시브 생성 금지 |
| 영구 보정 | 승인된 사건/효과ID를 출처로 가진 보정 개체 | 실제 보상 콘텐츠·영구 성장 아이템은 별도 승인. 무제한 반복 보상 없음 |
| 장비/일시 상태 | 최종 능력에 반영하고 출처 분해 표시 | 캐릭터 레벨 성장이 아님. 물품·상태 실행은SYS-04/05 소유 |

고정 성장표의 성향은4인 원문을 참고하되 수치·기술명·초기 레벨은 정식 시나리오로 확정하지 않는다. 역할 자격과 전투 기술은 별도 정의다. 스탯 증가가 자동으로 상인 자격·흥정률·새 이동수단 이용권을 주지 않는다.

`SkillDefinition`은 기술의 종류/공개 이름/사용 영역, `SkillRank`는 랭크별 효과 참조, `SkillCost`는 해당 랭크의 비용, `SkillUnlockRule`은 인물별 조건을 정의한다. 현재 랭크·습득 사실은 실행 상태다. 이미 습득한 기술은 표시하고, 잠긴 기술은 공개 조건이 충족된 경우에만 습득 조건을 보여준다. 공개 조건이 아직 거짓이라는 이유로 유효한 기술 습득을 막지 않는다. 미공개 사건명·미래 인물은 잠금 사유에서도 숨긴다.

**UI:** 성장 탭은 다음XP·다음 성장 미리보기·공개된 기술 해금 조건을 표시한다. 기술 탭은 습득/잠김/조건 미공개·현재 랭크·자원 비용·사용 영역을 구분한다. 자동 습득형 기술에 무의미한 `배우기` 확인 버튼을 붙이지 않는다. 필드 기술의 실제 사용은SYS-04/05와의 효과 계약 승인 후 별도로 구현한다.

## 8. 캐릭터 리소스 관리

### 8.1 승인된 HP+SP 구성

전투 인물은 HP와 공통 기술 자원SP를 사용한다. SP는검술·기계·지원·회복등기술비용이며생존피로/허기/이동스태미나가아니다. 전투 종료 후남은HP/SP는유지하고,실제레벨상승에서는새최대치로모두회복한다. 별도MP·배고픔·스트레스·노화능력감소를추가하지않는다. 부활외일반회복의양/가격/시간은해당콘텐츠검토사항이다.

| 자원/값 | 소유·수명 | 감소/증가 | 초기화/표시 |
|---|---|---|---|
| 현재HP | 실제 인물 개체, 전투/필드 간 보존 | 검증된 피해/회복/소모 결과 | 최초 생성 시 정책 적용. 전투 종료·재합류·파티 전환으로 전량 회복하지 않음 |
| 현재SP | 실제 인물 개체, 전투/필드 간 보존 | 확정 기술 비용/허용 회복 결과 | 기본안은 전투 종료 자동 충전 없음. 실제 시간으로 자동 재생하지 않음 |
| 누적XP | 주요 인물 개체에 지속, Lv100 이후도 누적 저장 | 모든 시스템의 명시된 XP 제공 효과 | 현재안은 성장 진행용. XP 차감/소비·레벨 하락은 별도 미승인 |
| ATB 게이지 | 전투 실행 상태 | SYS-05의 충전/행동 규칙 | 캐릭터SP와 별개. 정확한 충전/시작치는SYS-05 |
| 화물·돈·날짜 | 파티/공통 시스템 | 각 소유자의 실행 | 캐릭터 자원으로 중복 저장하지 않음 |

### 8.2 선택·예약·지급·결과

1. 목록/대상/비용 미리보기에는 실제 차감이 없다. 미리보기는 현재/필요/실행 후 예상값을 보여준다.
2. 실제 명령 등록에 자원 예약이 필요하면 `reservation_id`로 구분한다. 사용 가능량은 현재량에서 같은 인물의 유효 예약 합계를 뺀 값이다. 예약은 소비가 아니다.
3. 실행 시작 직전에 개체 생존/행동 조건·현재 습득 랭크·현재 비용·대상·예약을 재검사한다. 여러 비용은 전부 가능해야 함께 지급한다. 일부 차감 후 실패시키지 않는다.
4. **승인:** 실제 실행 시작에 SP 비용을 한 번 차감한다. 실행 전 취소는 SP를 소모하지 않고 예약만 해제한다. 실행 후 빗나감/저항은 환불하지 않는다. **남은 제안:** 그 밖의 효과0/특수 중단 환불은 해당 기술의 전투 계약에서 구분한다.
5. 시스템 처리 실패는 비용/효과/영수증을 함께 롤백한다. 정상적인 빗나감은 시스템 실패가 아니다. 실행 결과는 고유 작업ID로 중복 소비/회복을 차단한다.

기본안의 기술 비용은 정수 SP 고정량이다. 자해형 HP 비용·가변 비율 비용·쿨다운은 기본안에 넣지 않는다. 기술별 기본0비용 동작은SYS-05가 정의할 수 있으나 그 자체로 SP를 회복시키지 않는다. 현재SP가 비용보다 적으면 불가 사유를 표시하고 자원을 변경하지 않는다.

### 8.3 상한 변화·회복·전투불능

- **승인:** 실제 레벨업은 새 최대치까지 전량 회복한다. 장비/버프 등 레벨업 외 최대치 증가는 현재량을 그대로 두고 감소는 새 상한으로 한 번 제한한다. 장비/버프 반복 변경으로 회복을 만들지 않는다.
- 예: HP100/200 → 상한300은100/300, HP250/300 → 상한200은200/200이다. 미리보기만 취소하면 실제 HP250/300이 유지된다.
- **승인:** HP0은전투불능이며전투승리XP를받지않고부활전까지활동할수없다. 부활아이템또는부활가능장소에서부활해야한다. 일반HP회복·레벨업·메뉴/지역전환으로부활시키지않는다. `life_state`의영구사망은별도명시결과와구분한다.
- **승인:** 전투불능 대상을 지정한 아이템 사용은 부활 아이템만 허용한다. XP·일반 회복·영구 성장 등 나머지 모든 아이템은 사용 불가 사유를 표시하고 소비/효과를 적용하지 않는다. 실제 실행 직전에도 대상 상태를 다시 검사한다.
- 회복약/기술/휴식은 소유 시스템이 유효한 출처·대상·회복량·소생 허용 여부를 요청한다. 실제 물품 소비·가격·휴식 시간은 해당 소유자가 원자적으로 연결한다. 단순 캐릭터 정보 조회에 회복/휴식 버튼을 가짜로 연결하지 않는다.
- 새 필드/새 전투/파티 변경/메뉴 닫기/로드는 회복 출처가 아니다. 장소의 부활 기능을 명시하며 모든 숙소를 자동 부활 장소로 취급하지 않는다. **승인:** 부활 후 HP/SP는 부활 아이템·장소별 테이블의 회복 규칙을 적용한다. HP가1 이상인 유효한 부활 결과를 검사하고, SP 유지/회복도 해당 설정을 따른다. 특정 회복량이나 SP 전량 회복을 임의 기본값으로 넣지 않는다. 실제 수치·아이템 소비·장소 비용/시간은 SYS-04/14 연결 검토 사항이다.
- 수동 명령 선택 중에는 전투 자원 재생·상태 지속시간·예약 관련 논리 시간도 전투의 다른 논리와 함께 정지한다. 현실 시간이 지났다는 이유로 회복·소모하지 않는다.

**UI:** HP/SP를 현재/상한으로 표시하고, 전투불능·성장 없음·자원 부족은 색만으로 표현하지 않는다. 기술 비용 미리보기는 필요SP/예약 제외 사용가능SP/확정 후 예상값을 보여준다. 레벨업 알림은 `최대HP 증가`와 `회복`을 구분한다. 캐릭터 정보 화면은 이 정보를 보여주되 필드에 전원 자원바를 상시 추가하지 않는다.

## 9. 관계·평판·공개 정보

개인 대 개인 관계와 인물/파티 대 세력/지역 평판은 주체/대상을 구분한다. 값이 미정/미공개인 것을0 또는 중립으로 처리하지 않는다. 관계 수치가 기술 위력·흥정·이동 권한에 영향을 주려면 별도 규칙/출처를 명시한다.

이번 기준안은 관계/평판의 식별·공개·저장 경계를 설계하고, 연속 수치의 범위/등급/변화량·보너스는 별도 검토 항목으로 둔다. [테이블 상세](Character_Data_Tables.md)의 관계 테이블은 준비 스키마이며 이번 레벨/자원 기준안의 활성 필수 테이블로 취급하지 않는다. 개인 성장에는 관계 수치를 숨겨 곱하지 않는다.

### 10.1 캐릭터 표현 에셋의 수명과 준비

**테이블 구조 제안:** 논리 에셋ID/불변 파일 리비전 → 아틀라스 영역 → 방향별 클립/프레임 → 인물별 외형/용도 → 컨텍스트 로딩 그룹으로 관리한다.3D 맵에 표시할2D 몸체는 발 기준점·trim·표현 배율을 가지며 이동/충돌 좌표와 구분한다. **승인된 표현 기준:** 필드8방향, 동작별5원본/3반전, 캐릭터 정보 화면 전용 초상 일러스트다. 실제 프레임 크기·표현 배율·동작/표정 수는 별도 검토한다. [표현 승인 기록](../../qa/approvals/character-visual-decisions-2026-10-24.json)을 따른다.

메뉴 아이콘/초상은 같은 인물의 정해진 슬롯을 사용한다. 정보 화면의portrait/default는 전용 일러스트로 연결하고 menu_icon/default는 같은 원본의 지정 얼굴 영역을 참조한다. 초상 표시 영역은320×400px이며 원본 해상도/구도는 아트 디자이너가 이 영역에 맞게 정한다. 장비 교체는 필드/초상의 기본 외형을 변경하지 않는다. [초상/외형/영역 결정](../../qa/approvals/character-portrait-layout-decisions-2026-10-24.json)을 따른다. 미공개 초상을 노출하지 않고 미납품/검토 상태를 정식 준비 완료로 취급하지 않는다. 메뉴 아이콘/정보 초상 실패는 이름 텍스트 유지와 아트 오류를 기록한다.

동일 파일은 여러 프레임/인물이 공유해도중복로드하지않는다. 화면/현장마다 획득한참조만해제하고,지연완료콜백이닫힌화면을되살리지않도록문맥토큰을검사한다. 로딩/실패/교체는HP/SP/XP·날짜를변경하지않는다. 실제파일해시/영역/프레임·키참조검사,인물외형·발고정·카메라가림·메모리/해제를구분해검수한다.

## 13. 사용자 검토 범위

§2의 승인 기준을 유지한다. HP0의 모든 XP 수령 제외·테이블 초기 기술 그대로 적용·레벨업 외 최대 자원 변경·SP 비용 시점/환불·부활 수단별 회복 규칙을 다시 질문하지 않는다. 곡선/계수·실제 초기값·합류 이후 기술 연쇄 처리·부활 수치/비용과 에셋 관리 세부를 확인한다. 수치 예시는 정식 밸런스와 구분한다.

검토 후 변경/확정할 선택은 [검토 요청표](Character_Review_Request.md)에 모았다. 승인된 정책을 기준으로 실제 성장 곡선/인물별 수치/기술별 비용을 조정하고, 그 다음 승인 범위의 목업/구현 계획을 작성한다. 이번 디자인 제출을 게임/HTML 구현 승인으로 취급하지 않는다.
