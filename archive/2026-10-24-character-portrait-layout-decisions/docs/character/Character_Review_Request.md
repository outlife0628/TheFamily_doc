# SYS-03 디자인 재검토 요청

상태: **성장/자원·필드8방향/좌우 반전·전용 초상 승인**. 수치/에셋 등 남은 정책을 하나씩 확인 중이다. 본문은 [캐릭터 디자인](03_Character_System_UI.md), [수치/상태 테이블](Character_Data_Tables.md), [에셋 테이블](Character_Asset_Tables.md)을 따른다.

## 승인된 성장 방식

성장A와6기본 스탯의 종류/역할, HP+SP가 승인됐다. 전투 종료 후 자원을 유지하고 실제 레벨업에서는 새 최대치까지 둘 다 회복한다. HP0인 전투불능 인물은 승리 XP를 받지 않고 부활 아이템/부활 가능 장소에서 부활해야 활동한다. 부활 아이템 이외 모든 아이템은 전투불능 대상에게 사용 불가다.

전투 XP는 실제 참가하고 승리 시 활동 가능한 주요 인물에게 개인별 고정량을 지급한다. 제외 몫은 재분배하지 않으며 대기·비참가·다른 파티는 해당 전투 XP를 받지 않는다. XP는 공통 성장 변수이므로 아이템을 포함한 어떤 시스템도 명시된 효과로 제공할 수 있다. 전투 참가 조건을 다른 제공 경로에 강제하지 않는다.

레벨 상한은100이며 MAX 이후에도 XP를 계속 누적·저장한다. 최초 합류 레벨은 파티 평균과 관계없이 캐릭터별 지정값을 적용하고 재합류는 기존 레벨/XP를 유지한다. 승인 항목은 다시 질문하지 않는다. [이번 XP·초기 레벨 승인 기록](../../qa/approvals/character-xp-decisions-2026-10-23.json)은 이전 핵심 결정 기록과 구분해 보존한다.

전투 외 XP도 지급 시 HP0인 인물을 수령 대상에서 제외한다. 최초 합류 기술/랭크는 테이블 초기값 그대로 적용하고 과거 레벨/사건으로 자동 추가하지 않는다. 레벨업 외 최대HP/SP 증가는 현재량 유지, 감소는 새 상한까지만 제한한다. SP는 실행 시작 시 차감하고 실행 전 취소는 무소모, 실행 후 빗나감/저항은 환불하지 않는다. 부활 HP/SP는 아이템·장소별 테이블의 회복 규칙을 적용한다. [초기 기술·자원 승인 기록](../../qa/approvals/character-initial-and-resource-decisions-2026-10-24.json)을 별도로 보존한다.

필드 스프라이트는8방향 표시·5방향 원본/3방향 좌우 반전으로 승인됐다. 좌우·앞 대각선·뒤 대각선은 각 쌍의 한쪽만 제작하고 반대쪽은 반전 사용한다. 캐릭터 정보 화면 초상은 별도 전용 일러스트다. [표현 승인 기록](../../qa/approvals/character-visual-decisions-2026-10-24.json)을 보존하며 실제 원화/크기/표정·메뉴 아이콘 제작 방식의 승인과 구분한다.

## 승인되지 않은 다른 설계 선택의 현재 상태

아래 항목은 현재 제안 상태를 유지한다. 이번 재검토의 주된 요청은 에셋 관리 보강안이며, 나머지가 자동으로 승인됐다는 뜻은 아니다.

| 선택 | 권고 기준안 | 다른 선택 시 영향 |
|---|---|---|
| 합류 이후 기술 처리 | 실제 레벨/사건 변화에 따른 조건 평가·연쇄 습득의 세부안 | 최초 합류는 초기 기술 그대로 적용하며 과거 조건 소급 평가 없음 |
| 자원 콘텐츠/특수 중단 | 실제 부활 수치/장소 비용·효과0/특수 중단 시 비용 계약 | 승인된 최대치 변경·SP 비용 시점/빗나감·저항 환불 없음·수단별 부활 회복 규칙과 구분 |
| 에셋 제작 세부 | 몸체 크기/기준점·동작/프레임 수·초상 구도/표정·메뉴 아이콘 재사용 | 필드8방향·5원본/3반전·정보 화면 전용 일러스트는 승인 기준 |
| 테이블 구조 | 정의/밸런스와 개체 상태 분리, 명시 레벨표, 영수증으로 중복 방지 | 기획자가 수치를 조정해도 현재 자원/XP를 초기화하지 않는 계약 필요 |

합류 이후 동일 처리의 연쇄 습득과 공통 공개 영수증 계약은 제안 상태를 유지한다. 승인된 성장 구조·상한·XP 수령/전투 분배·초기 레벨/기술·최대치 변경·SP 비용 시점·수단별 부활 회복 방식을 다시 질문하지 않는다.

## 에셋 보강안에서 검토할 기준

- 파일 경로 대신 안정ID·불변 리비전·용도별FK로 인물과 아트를 연결한다.
- 필드 몸체·메뉴 아이콘·정보 화면의 전용 초상은 해당 문맥의 필수 연결을 검사한다. 그림자·다른 화면의 초상은 그 문맥 정책을 따른다. 런타임 아이콘/초상 읽기 실패는 이름 텍스트와 오류 기록을 유지한다.
- 필드 방향은8개이며 동작별5개 원본과3개 반전 연결을 검사한다. 각 좌우 쌍의 한쪽을 반전 재사용하는 기준을 유지하고, 원화 크기/구도·동작/프레임 수는 별도로 검토한다.
- 여러 인물/프레임이 같은 파일을 공유해도1회 로드하며 화면별 참조를 해제한다. 파일/캐시 오류가HP/SP/XP·실제 위치를 바꾸지 않게 한다.
- 실제 아트·엔진 출력이 없는 fixture는 메타데이터/산술 검사용이며 납품/승인/실행 통과로 보고하지 않는다.

## 수치 승인과 분리할 항목

레벨 상한100과 캐릭터별 지정 초기 레벨 방식은 승인 기준이다. 6기본 스탯의 범위·파생 계수·인물별 실제 시작값/증가값·초기 레벨 값·상한5의 시험 XP 곡선·기술A/B·SP 비용은 검토/시험값이다. 4인 시작 파티·초기 기술·경제 수치·최종 밸런스까지 자동 확정하지 않는다.

실제 적/사건XP량·최종 피해/명중/ATB·회복품/휴식 조건·정식 상인 자격 인물·관계/평판 등급/보너스는 각 소유 문서와 남은 협의 항목을 구분했다. 캐릭터의 스탯/레벨/성장/자원 처리 설계를 그 이후로 미룬다는 뜻이 아니다.

## 검토 요청

에셋 관리 테이블·인물/용도 연결·프레임/방향·로딩/저장/실패 정책에서 수정할 항목을 확인해 달라. 성장 방식A는 승인대로 유지한다. 현재 산출물은 문서와 합성 메타데이터 사례이며 실제 스프라이트/아이콘 제작·새HTML·Godot 구현은 착수하지 않았다.
