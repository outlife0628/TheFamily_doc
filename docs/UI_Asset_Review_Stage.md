# SYS-02 UI 에셋 검수 단계

상태: UI 아트 에셋 생성·사용자 검수 단계. HTML/CSS/JavaScript 목업 수정 중지.

## 적용 기준

`reference/art/approved_direction/simplified_movement_concept.png`의 실제 버튼 윤곽, 금속 테두리, 종이 결, 짙은 표면, 얇은 모서리 문양, 작은 나침반을 부품 단위로 참고한다. 단순 색상 대입만으로 아트 적용을 완료했다고 하지 않는다.

글자·지명·수치·선택 상태·입력은 에셋 이미지에 굽지 않는다. 기준 화면 1920×1080·글씨 프로필 100%, H-2/M-1/D-1/B-1 구조와 공용 행동 슬롯은 유지한다. 미니맵 틀의 모양이 HUD 위치 변경을 뜻하지 않는다. 다른 게임 지명·초상·레벨·퀘스트 수·지도 지형을 도입하지 않는다.

## 1차 검수 에셋

1. 금색 주 행동 버튼의 빈 표면.
2. 짙은 보조/취소 버튼의 빈 표면.
3. 밝은 종이 상세 패널.
4. 짙은 헤더와 종이 본문으로 구성한 출발 확인창 틀.
5. 짙은 여정/공용 패널.
6. 원형 미니맵 외곽 틀.
7. 목표 하나를 담는 짙은 목표 카드.
8. 작은 금색 나침반 장식.

각각 별도 PNG 생성본으로 검토한다. 가변 문구를 놓을 중앙은 비워 두고, 외곽이 필요한 에셋은 투명 배경으로 만든다. 이미지 생성 결과의 알파·중앙 여백·형태·재질을 직접 확인하고, 생성 품질과 사용자 승인 상태를 분리한다. 정확한 배포 크기·9-slice 경계·포커스/불가 등 상태별 변형은 승인 전 확정하지 않는다.

## 진행 게이트

개별 에셋 생성 → 에셋 시각 확인 → 사용자 에셋 검수/수정 → 승인한 에셋과 필요한 상태 변형 확정 → 실제 HTML 적용 → 실행·시각·지침 검수 → 사용자 목업 검수.

승인된 단순화 방향 자체를 다시 고르는 절차가 아니다. 사용자 검수 전 목업 수정이나 다음 시스템 작업을 진행하지 않는다. 기존 구현·원문·이미지는 삭제하거나 덮어쓰지 않는다.
