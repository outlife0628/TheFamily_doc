# 캐릭터 에셋 테이블 독립 검토

검토 대상: Character_Asset_Tables.md, 캐릭터 디자인의 에셋/성장 승인 절, 게임 데이터 테이블의 새 에셋FK. 별도 에셋/데이터 엔지니어 관점에서 읽기 전용 builder check를 수행했다. 실제 엔진/아트 테스트가 아니다.

검토자가 찾은 중요 질문은 기술·HP/SP·역할 아이콘의 로딩 루트와 필수 여부였다. 인물 외형 바인딩만 따라가면 이 정의 아이콘의 파일이 빌드/런타임 목록에서 빠질 수 있었다.

보강한 계약:

- CharacterAssetBinding은 인물의 몸체/메뉴 아이콘/초상 등5종 슬롯을 유지한다.
- 기술/자원/역할 정의의icon_region_id는 별도 직접 루트로AssetRegion→AssetRevision을 해석한다. 공개·표시 정의ID를 요청하며 임의 경로를 입력하지 않는다.
- SlotPolicy에skill_icon/resource_icon/role_icon을 추가했다. 기술·HP/SP 아이콘은 해당 활성UI의 필수 연결, 역할 아이콘은 선택 연결이다. null 형식과 필수 정책을 구분한다.
- 빌드는 활성 콘텐츠 전체의 참조 폐포, 런타임은 현재 공개/표시하는 하위 집합을 사용한다. 후반 기술/인물이 처음에는 미공개라는 이유로 빌드에셋을 누락하지 않는다.
- 축소 fixture에 정의 아이콘 요청·필수null 거절·역할null 허용 사례를 추가했다.

검토자는 요청한 나머지 범위에서 중요한 추가 질문을 찾지 못했다고 보고했다. 수정 후 별도의 재검토를 새로 통과했다고 주장하지 않는다. 정합성 검사는document-checks.json에 분리 기록한다.
