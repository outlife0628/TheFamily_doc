## 1. 목적과 범위

The Family: Father of Steam은 가족과 함께 생활 기반을 지키고 사건의 진실을 추적하는 단일 플레이어 스팀펑크 판타지 JRPG다. **맵은 3D 공간으로 제작하고, 2D 픽셀 아트 캐릭터가 그 공간 안을 이동하는 혼합 표현 방식**을 사용한다. 옥토패스 트래블러와 같은 3D 배경·2D 픽셀 캐릭터의 조합을 표현 목표로 삼는다. 본 문서에서 이를 ‘2.5D 표현’으로 부르되, 2D 타일맵만으로 구성하는 게임을 뜻하지 않는다.

기본 RPG의 탐험·대화·성장·준비·전투·목표 진행이 성립한 뒤 직접 교역·운송·사업을 연결한다. **Godot를 게임 엔진으로 사용하고 Steam 출시를 우선**하며, 이후 콘솔 출시를 고려한다. 코드·에셋·사운드 등 제작 도구와 AI 모델은 작업 목적에 따라 선택·추가할 수 있다.

이 문서는 전체 게임 개요와 화면의 목적·연결·간략 구성을 정한다. 능력치 공식, 구체 이동 조작, 인카운터 확률, 퀘스트 목표 산식, 상세 UI 좌표·아트·HTML을 한꺼번에 정의하지 않는다.

**생산 순서와 작품의 주제는 다르다.** 기본 RPG를 먼저 설계하는 것은 사업·교역·가족·조사의 중요성을 없애는 뜻이 아니다. 회사의 반복 실무를 줄여도 플레이어가 직접 사람·물건·이동·큰 투자를 결정하는 경험은 유지한다.

정확한 시작 월일·달력의 세부 단위·초기 자금·초기 레벨·출발 맵은 아직 확정하지 않는다. **완납에 의한 즉시 종료, 지정 시나리오에 의한 상환 차단, 10년 기한과 해제 원칙**은 적용 기준이다. 상환 차단과 시간 제한 해제는 같은 메인 사건의 동일한 적용 시점에 반영한다. 정확한 Act·증거·사건 안의 적용 지점은 후속 이벤트·퀘스트 설계에서 지정한다.

### 2.1 3D 공간과 2D 픽셀 캐릭터의 표현 기준

마을·실내·야외·던전 등 플레이 공간은 3D 맵을 기준으로 설계한다. 캐릭터는 2D 픽셀 아트 스프라이트로 표현하며 실제 위치와 이동은 해당 공간의 규칙을 따른다. 픽셀 캐릭터를 사용한다는 이유로 이동·충돌·가림·고저차를 2D 타일 좌표만으로 확정하지 않는다.

이 구성만으로 자유 카메라, 점프, 완전 자유로운 3축 이동, 특정 조명·심도 효과를 채택한 것은 아니다. 카메라 각도·회전 허용·이동 평면·고저차·가림 처리·스프라이트 방향은 SYS-02에서 검토한다. 전투 전용 필드의 카메라·배치·대상 표시는 SYS-05에서 같은 표현 기준에 맞춰 정한다.

HUD·메뉴·대화·버튼은 월드 아트와 분리된 공용 화면 UI로 구성한다. 공간 표현이 3D라는 이유로 승인된 H-2 / M-1 / D-1 / B-1이나 1920×1080 UI 기준을 바꾸지 않는다.

### 2.2 제작 도구와 출시 범위

Godot는 게임 실행의 엔진 기준이다. Codex·Claude Code와 추가 AI 모델은 개발·제작을 돕는 도구이며, 이 도구들을 플레이어가 설치해야 게임이 동작하는 요구로 만들지 않는다. 에셋·사운드 제작 도구도 게임 규칙·데이터의 원본을 대신하지 않는다.

Windows 11은 현재 개발 PC 환경으로 기록한다. Steam의 구체 지원 운영체제·최소 사양·지원 언어는 출시 범위 검토에서 정하고, 콘솔 기종과 포팅 도구·일정·호환 성공을 지금 확정하지 않는다. 콘솔을 고려해 입력 의미와 장치별 표시를 분리하되, 현 단계에서 모든 콘솔 대응이 완료되었다고 표시하지 않는다.

특정 AI 모델이나 제작 도구의 추가는 게임 시스템 변경 승인이 아니다. 생성한 이미지·에셋·음원은 시연·검토·배포용 승인 상태를 구분하며, 품질·사용 조건·엔진 반영 가능 여부를 개별 확인한다.

## 3. 기본 플레이와 확장 플레이

### 3.1 기본 RPG 흐름

`사람·장소와 만남 → 목표·상황 이해 → 장비·아이템·파티 준비 → 이동·현장 탐험 → 조사/대화/전투 → 결과 반영 → 필요 시 보고 → 보상·성장 → 다음 선택`

목표가 없는 자유 탐험과 일반 거래도 가능하다. 모든 이동을 퀘스트 수락에 종속시키지 않는다. 목표 추적은 안내 선택이며, 수락·실행·완료·보상 지급과 같은 행동이 아니다.

### 3.2 교역·사업의 연결

`파티 구성 → 이동수단·화물 준비 → 현지 흥정·매입 → 다른 도시 이동 → 현지 흥정·판매 → 인력·운송수단·사업·채무에 재투자`

시드리아는 본거지지만 매 거래의 필수 경유·정산 장소가 아니다. 현지 판매대금은 현지에서 다음 구매에 사용한다. 구매·도착·판매·귀환은 서로 다른 행동이다. 고아원 채무 상환은 허용 구간에서만 선택할 수 있으며, 마지막 원금을 상환하면 반복 플레이로 돌아가지 않고 채무 완납 엔딩으로 종료한다.

사업의 일상 영업·장부·일반 적재/하역·승인 계약의 정기 처리는 시스템이 수행한다. 상품·수량·흥정·목적지·이동수단 구매/개조·편성·큰 투자는 플레이어에게 남긴다. 시스템이 승인 없는 고용·구매·매각·채무 상환을 대신 결정하지 않는다.

### 3.3 원작 진행과 플레이 검증의 구분

게임 초반의 자유 생계와 Act 1 해금은 구분한다. 현재 가용자금 조건 충족 시 시작 가능 목표가 열리지만, 플레이어가 고아원 또는 공동숙소에서 직접 시작한다. 해금 즉시 강제 컷신·수락으로 만들지 않는다. 자유 생계 단계에 머무를 수 있어도 시간 제한이 유효한 동안에는 공통 날짜와 10년 종료 조건을 따른다. 메인 이벤트 시작을 미룬다고 기한이 정지하거나 연장되지 않는다.

마을 NPC → 대화 → 목표 → 현장 → 전투 → 보고의 검증 장면을 제작하더라도, 특정 Act의 사건을 프롤로그로 옮기거나 원작에서 없는 대사를 정식 콘텐츠로 등록하지 않는다. 검증용 독립 사례가 필요하면 별도 승인·표시한다.

### 5.1 화면 진입점

마을의 상인·역·길드·은행·숙소와 주메뉴는 필요한 경우 같은 콘텐츠 UI에 연결한다. 다만 메뉴를 열 수 있다는 것과 원격으로 거래·수리·합류할 수 있다는 것은 다르다. 실제 위치·영입/거래 자격·수량·가용 상태를 각 시스템에서 확인한다.

### 5.2 정보를 간략하게 보여주는 기준

필드에는 현재 조작 파티의 행동과 관련된 정보만 보여준다. 전체 8개 파티의 HP·회사 장부·정기 지출·작품명은 상시 노출하지 않는다. 가격·날짜·적재량은 실제로 판단할 화면에서 보여준다.

목표 갱신·일반 획득·정상 지급은 짧게 알리고 기록에서 다시 확인할 수 있게 한다. 읽지 않았다고 결과를 보류하거나 다시 읽었다고 재적용하지 않는다. 미해결 위험은 잠깐의 알림이 끝났다는 이유만으로 흔적 없이 사라지지 않는다.

10년 기한과 완납 시 게임 종료는 새 게임의 전제 및 관련 자금·진행 화면에서 안내한다. 마지막 상환 확정 전에는 이후 메인 시나리오를 진행할 수 없음을 명확히 고지한다. 기한 임박 경고 시점은 시간 시스템에서 검토하며, 평소 HUD를 큰 장부로 바꾸지 않는다. 상환 차단 후에는 고아원 상환 입력을 차단하고 현재 공개된 사유를 표시한다. 지정 메인 사건에서 상환 차단과 기한 해제를 함께 알리고 종료 카운트다운을 없앤다. 하나의 알림 안에서도 상환 불가와 10년 종료 조건 해제의 의미를 각각 명확히 표시한다.

### 6.2 공용 부품 원칙

창 표면·문맥 헤더·탭·선택 목록·상세/비교·수량·대상·상태 행·대사/선택지·행동 영역·확인창·알림·입력 안내를 공용으로 사용한다.

컴포넌트의 원본과 입력 규칙은 하나로 유지한다. 각 콘텐츠 기획에는 해당 부품에 들어갈 실제 정보와 행동을 기획한다. 장비·퀘스트·교역에 같은 문장을 반복해서 표시하는 것을 공용화라고 보지 않는다.

### 6.3 공통 행동 슬롯

| 역할 | 기본 상대 위치 | 변하지 않는 것 |
|---|---|---|
| 주 행동 | 하단 오른쪽 끝 | 사용·장착·수락·구매·실행으로 문구가 바뀌어도 슬롯 유지 |
| 취소·이전·닫기 | 주 행동 바로 왼쪽 | 주 행동이 없어도 대신 오른쪽 끝으로 옮기지 않음 |
| 보조·상세·도움말 | 하단 왼쪽 | 보조 기능임을 명확히 구분 |
| 탭 이동 | 상단 고정 영역 | 같은 의미 입력과 순서 |

동일 템플릿·해상도·글씨 프로필의 버튼 크기와 위치는 고정한다. 일반 메뉴와 소형 모달은 자신의 경계를 기준으로 하므로 물리적인 절대좌표를 전 화면에서 동일하게 강제하지 않는다. 필드의 대상 안내는 작은 표식, 전투 명령은 고정 명령 영역을 사용한다.

긴 본문은 스크롤하되 핵심 결과·비용·주 행동·취소를 밀어내지 않는다. 사용 불가 상태는 이유를 제공하며 색만 바꾸어 표현하지 않는다. 기본·선택·포커스·사용 불가·처리 중·오류를 구분한다.

### 6.4 입력과 복귀

선택·호버·가격 미리보기는 실행이 아니다. 실제 사용·장착·계약은 조건을 다시 확인하고 확정한다. 하나의 확인창이 활성화되면 배경 입력을 차단한다. 취소하면 이전 인물·항목·스크롤·화면 상태로 돌아간다.

읽기 단계에서 누른 결정 키가 새 선택지의 수락까지 이어지지 않도록 입력을 구분한다. 한글 조합 Enter를 확정으로 처리하지 않는다. 키보드·게임패드의 의미 입력과 화면 안내를 함께 재지정하는 규격은 SYS-16에서 상세 검토한다.

## 8. 시간·종료 조건·저장의 공통 연결

### 8.1 행동 기반 공통 날짜

운영 날짜와 전투의 행동 준비 시간, 화면의 애니메이션 시간은 같은 시계가 아니다. 메뉴·대화·전투 명령을 읽는 현실 시간은 공통 날짜에 더하지 않는다. 어떤 현장 행동에 얼마나 시간이 드는지는 SYS-02와 SYS-11에서 정한다.

여러 파티에 활동을 지정하고 공통 시간을 진행하면 해당 기간만큼 병행 처리한다. 화면마다 시간이나 월말 비용을 별도로 더하지 않는다. 지급·보상·화물 변화·퀘스트 완료에는 동일 결과의 중복 반영을 막는 식별이 필요하다.

### 8.2 고아원 채무 상환과 즉시 완납 엔딩

**상환이 허용된 상태에서 고아원 채무를 실제로 완납하는 순간, ‘채무 완납 엔딩’으로 게임을 종료한다. 종료된 해당 진행에서는 이후 메인 시나리오를 진행할 수 없다.** E.C.5010을 기다리거나, 완납 후 계속 플레이할지를 다시 선택하는 방식이 아니다.

| 상황 | 판정과 결과 |
|---|---|
| 상환 가능, 일부 금액을 상환하고 원금이 남음 | 허용된 금액만 차감하고 계속 진행 |
| 상환 가능, 마지막 원금을 모두 상환 | 상환과 동시에 채무 완납 엔딩·게임 종료 확정 |
| 채무 전액에 해당하는 돈만 보유 | 상환·엔딩을 자동 실행하지 않음 |
| 상환액을 입력·검토했지만 취소 | 돈·원금·진행 상태 변경 없음 |
| 시나리오에 의해 상환이 차단됨 | 부분 상환·전액 상환 모두 불가. 채무 완납 엔딩 발생 불가 |

완납 판정은 **고아원 채무에 대한 유효한 실제 상환 결과**를 사용한다. 증거 확인·법적 상태 변경·표시용 잔액 조정 등으로 계정 상태가 바뀌는 것을 ‘갚아서 완납함’으로 처리하지 않는다. 잔액 숫자 하나만을 모든 엔딩의 조건으로 사용하지 않는다.

채무 완납 엔딩은 미상환·사망 등의 게임오버와 다른 종료 원인이다. 메인 시나리오를 완료한 엔딩으로 표시하거나, 이후 메인 퀘스트를 자동 완료하지 않는다. 이 엔딩의 구체 장면·대사·평가·별도 보상은 SYS-09/10/16에서 검토한다.

다른 파티·사업의 활동이 남아 있어도 완납한 해당 진행을 유지한 채 후속 메인 시나리오로 넘어가지는 않는다. 종료 기록의 저장·자동저장·이전 저장 불러오기·새 게임 등의 메뉴 정책은 SYS-16에서 정한다. 완납을 이유로 기존 저장 파일을 삭제하거나 덮어쓰는 규칙은 추가하지 않는다.

### 8.3 메인 시나리오에 의한 상환 차단과 기한 해제

**채무가 부당했다는 증거가 등장하는 지정 메인 사건에서 고아원 채무의 부분·전액 상환을 차단하고, 같은 적용 시점에 10년 시간 제한을 해제한다. 이후에는 채무 완납 엔딩과 E.C.5010 기한에 따른 채무 불이행 게임오버가 발생하지 않는다.**

차단 조건은 기획자가 지정하는 메인 시나리오 진행 사건이다. Act 번호, 어떤 증거와 사건인지, 연출 안의 어느 시점에 적용할지는 SYS-09/10에서 정한다. 일반적인 의혹·단서 열람·임의의 증거 아이템 획득을 곧바로 차단 사건으로 바꾸지 않으며, 사용자가 지정하지 않은 ‘최종 법원 판결’을 추가 선행 조건으로 요구하지도 않는다.

| 구분 | 적용 원칙 |
|---|---|
| 적용 대상 | 애슈포드 고아원 채무의 상환. 다른 정상 계약의 지급·사업장 할부·급여·용병 유지비를 일괄 금지하지 않음 |
| 차단 범위 | 상환 UI, 은행/NPC 대화, 이벤트 명령 등 고아원 채무를 갚는 모든 실행 경로 |
| 열린 상환창 | 차단 사건 이후 확정하려는 요청은 현재 상태를 다시 검사하고 거절. 돈과 원금 변경 없음 |
| 완납 엔딩 | 차단 이후에는 잔액이나 보유 자금과 무관하게 진입 불가 |
| 기록 | 이전에 지급한 금액·날짜와 차단 사유는 보존. 과거 상환을 소급해 완납 엔딩으로 처리하지 않음 |
| 반환·법적 정리 | 이미 낸 돈의 환급, 잔여 원금의 취소/말소, 소송·보상은 별도 시나리오·경제 정책. 차단만으로 자동 확정하지 않음 |

상환 차단은 ‘잔액을 0으로 만들고 완납 처리’가 아니다. 플레이어가 알게 된 사실의 범위 안에서 상환 불가 사유를 보여주고, 관련 기록을 읽을 수 있게 한다. 이 기능은 상환을 중단시키는 시나리오 전환이며 게임의 종료 자체를 뜻하지 않는다.

### 8.4 10년 기한과 시나리오에 따른 해제

**게임은 E.C.5000에 시작한다. 시간 제한이 유효한 상태에서 게임 내 10년이 경과해 E.C.5010의 기한에 도달하고 고아원 채무가 남아 있으면, 채무 불이행 게임오버로 자동 종료한다.** 이미 완납했다면 그 순간 게임이 종료되므로 ‘완납 상태로 계속 플레이하다가 10년째에 종료’하는 정상 플레이 분기는 두지 않는다.

**상환을 차단하는 지정 메인 사건에서 캠페인의 10년 시간 엔딩 조건을 동시에 해제한다.** 해제 상태에서는 잔여 채무나 날짜가 E.C.5010을 넘었다는 이유로 시간 엔딩·채무 기한 게임오버를 발생시키지 않는다.

| 상태 | 적용 결과 |
|---|---|
| 진행 중, 기한 전, 상환 허용 | 부분 상환 또는 완납 종료가 가능하며 메인 시나리오 진행 가능 |
| 실제 완납으로 종료 확정 | 채무 완납 엔딩. 이후 메인 시나리오·일반 활동으로 복귀하지 않음 |
| 지정 메인 사건의 전환 적용 | 상환·완납 엔딩 불가와 10년 기한 해제를 동시에 적용. 진행은 계속됨 |
| 진행 중, 시간 제한 유효, 기한 도달, 채무 미상환 | 채무 불이행 게임오버 |
| 진행 중, 시간 제한 해제 | E.C.5010 도달·초과만으로 종료하지 않음. 사망·주요 시나리오 실패 조건은 유지 |

플레이어의 보고 열람이나 확인 버튼이 기한 판정의 조건이 되어서는 안 된다. 긴 활동도 유효한 종료 경계를 넘겨 이동·수입을 먼저 끝낸 뒤 뒤늦게 실패 처리하지 않는다. 정확한 시작/기한 월일과 같은 시간에 발생하는 사건의 우선순위는 SYS-11에서 검토한다.

해제되는 것은 **10년 기한에 따른 캠페인 종료 조건**이다. 공통 날짜, 이동·사업·급여·개별 의뢰의 기한을 모두 없애는 것이 아니다. 해제 여부는 단순 잔액이나 Act 설명 열람이 아니라 지정된 실제 시나리오 진행으로 판정한다.

#### 시나리오 전환의 동시 적용

상환 차단과 10년 시간 제한 해제는 **동일한 메인 사건의 동일 적용 시점**에 처리한다. 실행·저장 중간에 하나만 적용된 상태를 정상 진행으로 남기지 않는다. 해당 사건의 재실행이나 저장 복원으로 해제 효과가 취소되거나 다시 적용되지 않게 한다.

이 전환은 채무 원금을 상환한 결과가 아니다. 채무 완납 엔딩을 발생시키지 않으며, 채무 계정의 법적 말소·기납부금 환급은 별도 정책이다. 전환 이후에도 공통 날짜와 다른 정상 계약, 급여·사업·개별 의뢰의 시간은 유지한다.

정확한 Act 번호·증거·연출 적용 지점은 SYS-09/10에서 정한다. 사건을 사전에 볼 수 있는 개발 목록이나 설명문 열람은 실제 사건 완료가 아니다.

### 8.5 시간 제한과 독립된 게임오버

시간 제한의 유효/해제와 관계없이 **주인공 크리스의 사망 또는 주요 시나리오의 결정적 실패가 확정되면 게임오버가 발생할 수 있다.** 상환 차단이나 시간 제한 해제는 무적·무실패 모드가 아니다.

다만 HP 0, 일시적인 전투불능, 일반 의뢰 실패, 부가 목표 미달을 곧바로 사망·캠페인 실패로 바꾸지 않는다. 해당 조건은 SYS-03/05/09/10에서 명시하며, 이야기상 패배 후 진행하는 사건은 그 후속 규칙을 따른다.

종료 원인은 **채무 완납 엔딩 / 메인 시나리오 정상 엔딩 / 기한 미상환 게임오버 / 주인공 사망 게임오버 / 주요 시나리오 실패 게임오버**를 구분한다. 개별 실패 후 재도전·불러오기·타이틀 복귀는 SYS-16에서 검토한다. 채무 완납 상태에서 메인 시나리오를 이어가는 선택은 제공하지 않는다.

### 8.6 같은 규칙의 UI·UX

| 문맥 | 표시와 행동 기준 |
|---|---|
| 시작 안내 | E.C.5000 시작·10년 기한·미상환 결과·완납 시 종료를 안내. 미래의 증거·차단 Act·음모를 미리 드러내지 않음 |
| 시간·자금 상세 | 현재 날짜·기한·잔여 원금·누적 상환·상환 가능 상태·시간 제한 상태를 구분. 확인되지 않은 잔여 일수를 만들어 표시하지 않음 |
| 부분 상환 | 차감액·상환 후 원금·남는 자금을 보여주며 완납이 아닌 동안 계속 진행 |
| 마지막 상환 | 실제 차감 전에 ‘완납하면 채무 완납 엔딩으로 종료되며, 이 진행에서 이후 메인 시나리오를 진행할 수 없다’고 안내. 명시적인 최종 선택을 한 번 받음 |
| 완납 확인의 취소 | 상환 전 인물·입력액·화면 문맥으로 복귀. 돈·원금·종료 상태 변경 없음 |
| 완납 확인의 확정 | 현재 상환 허용 여부와 자금을 재검사. 유효한 마지막 상환과 엔딩을 함께 확정하며, 지급 후 계속 진행할지 다시 묻지 않음 |
| 상환 차단 사건 이후 | 부분/전액 상환 입력과 실행을 차단. 공용 상세에서 공개된 사유·과거 상환 기록을 열람. 완납이나 법적 면책으로 혼동하게 표시하지 않음 |
| 시간 소모 행동 | 행동 전후 예상 날짜와 유효한 기한을 확인. 기한 임박 경고의 상세는 SYS-11 |
| 시간 제한 해제 | 상환 차단과 같은 사건에서 두 효과를 안내하고 카운트다운을 제거. 달력·다른 활동은 계속 유지 |
| 엔딩·게임오버 결과 | 실제 종료 사유와 허용된 경로를 안내. 채무 완납에 메인 시나리오 ‘계속하기’를 제공하지 않음 |
| 콘텐츠 대기 | 제공 구간의 콘텐츠 대기는 엔딩·게임오버가 아님. 날짜·생산·비용·이동을 함께 정지 |

마지막 상환의 확인 문구·버튼 예시는 **표현 예시**로 `취소` / `완납하고 종료`를 사용할 수 있다. 주 행동은 하단 오른쪽, 취소는 바로 왼쪽이며 안전한 취소에 초기 포커스를 둔다. 이미 마지막 상환의 효과를 충분히 고지한 최종 확인 단계가 있으면 같은 확인을 연속해서 추가하지 않는다.

닫힌 상환창이나 이전 견적에서 유입된 입력이 시나리오 차단을 우회하지 않도록 실행 단계에서도 조건을 확인한다. 상환 차단 사유·완납 결과·시나리오 해제는 텍스트와 실제 상태가 일치해야 한다. 차단과 기한 해제는 저장에서도 같은 전환 결과로 보존한다. 이것은 UI 명세이며 새 화면·HTML 제작 완료를 뜻하지 않는다.

### 8.7 저장과 후속 시스템의 연결

각 시스템 기획은 자신의 보존 상태와 중단 시점을 함께 작성한다. 공통 날짜·잔여 원금·누적 상환과 함께 **상환 허용/차단 상태·차단 사건, 시간 제한 유효/해제 상태·해제 사건, 종료 여부·원인·마지막 상환 결과**를 보존한다. 필드명·자료형은 후속 구현 설계에서 정한다.

시나리오에 의한 상환 차단·시간 제한 해제가 적용된 저장은 그 상태로 복원한다. 실제 완납으로 종료된 진행을 일반 진행 중으로 복구하지 않는다. 이전 시점 저장을 불러오는 것과 끝난 진행을 그대로 이어가는 것은 별개이며, 슬롯·자동저장·복귀 UI는 SYS-16에서 검토한다.

상환 성공과 채무 완납 엔딩은 같은 확정 결과로 처리해 ‘돈만 냈는데 엔딩은 적용되지 않은 진행’ 또는 중복 차감을 만들지 않아야 한다. 연출 스킵·보고 재열람·화면 복귀가 완료된 상환·엔딩의 재실행이나 취소를 뜻하지 않는다.

날짜 경계, 마지막 상환, 상환 차단·기한 해제의 공통 전환 사건, 사망·주요 실패가 같은 시점에 겹칠 때의 우선순위는 미정이다. 단, 공통 전환 사건 자체의 두 효과는 분리하지 않는다. 특정 연출 순서를 임의로 채택하지 않는다. E.C.5010 에필로그의 시나리오상 시간 배치도 별도 검토하며, 이를 이유로 해제된 기한을 되살리지 않는다.

## 10. 기본 시스템·UI 검토 기준

이 항목은 문서 검토 기준이다. 실제 게임이나 새 목업을 실행해 합격했다는 뜻이 아니다.

| 확인 항목 | 문서에서 확인할 것 |
|---|---|
| 표현 방식 | 3D 맵과 그 안에서 이동하는 2D 픽셀 캐릭터를 구분하고, 이동·카메라 상세를 임의 확정하지 않았는가 |
| 제작·출시 | Godot를 엔진으로, AI·제작 도구는 확장 가능하게, Steam 우선과 콘솔 고려를 구분했는가 |
| 완납 종료 | 실제 완납 즉시 채무 완납 엔딩이며 이후 메인 시나리오 진행이 불가능한가 |
| 상환 차단 | 지정 메인 시나리오 이후 부분/전액 상환과 완납 엔딩을 차단하며 사유를 안내하는가 |
| 마지막 상환 UI | 차감 전에 종료 효과를 고지하고, 취소 시 무변경·확정 시 즉시 종료로 연결하는가 |
| 10년 종료 | 기한이 유효한 E.C.5010 도달의 미상환 게임오버와 기한 해제 상태를 구분했는가 |
| 해제와 다른 실패 | 시나리오 해제로 시간 종료만 제거하고 사망·주요 실패의 게임오버 가능성을 유지했는가 |
| 동시 적용과 상세 경계 | 차단/기한 해제를 함께 적용하고, 정확한 사건·HP 0/사망 관계는 후속 결정으로 구분했는가 |
| 기본 RPG 선행 | 이동·대화·퀘스트·전투·준비/회복·저장에 각 담당 문서가 있는가 |
| 차별 시스템 보존 | 직접 흥정·도시 이동·차량 성장·공통 파티가 유지되는가 |
| 화면 목적 | 필드·메뉴·대화·전투에서 현재 행동과 필수 정보가 구분되는가 |
| 승인 범위 | 기존 결정·본 초안의 연결 제안·후속 결정 대기가 섞이지 않는가 |
| UI 통합 | 콘텐츠 규칙을 정한 곳에서 표시·선택·취소·결과까지 기획하도록 연결했는가 |
| 단계 경계 | 다음 시스템의 미정 규칙을 이 문서에서 임의로 정하지 않았는가 |
| 신규 자료 상태 | 전체 시스템 완성본·새 HTML·상용 아트·실기 검증으로 오인할 표현이 없는가 |

## 11. 승인 범위와 다음 단계

SYS-01의 게임 개요·3D 맵/2D 픽셀 캐릭터·제작 도구·Steam 우선·핵심 플레이·종료 조건·화면 역할·공용 조작을 1단계 기준으로 사용한다. **채무 부당성 증거가 등장하는 지정 메인 사건에서 부분/전액 상환 차단과 10년 시간 제한 해제를 동시에 적용**한다.

§9의 세부 미정 항목은 해당 시스템에서 검토한다. SYS-01 승인으로 성장 공식·이동 방식·카메라·이벤트 번호·달력의 정확한 월일·배포 아트·게임 코드가 일괄 확정되는 것은 아니다.

다음 단계는 [SYS-02 이동 시스템·UI](02_Movement_System_UI_Ver0.3.md)다. 3D 공간의 탐험과 지역 연결, 입력·카메라·상호작용·지도·도시 간 이동을 시스템과 UI의 같은 기능 단위로 검토한다. SYS-02 승인 전 SYS-03 이후의 새 상세 설계로 진행하지 않는다.

자료 기준은 사용자 결정과 승인된 UI 지침 Ver0.8.1, 원작의 해당 세계·시나리오다. 정확한 전환 Act를 원작의 개괄적인 문장으로 추정해 지정하지 않는다. 현재 문서에 변경 연혁을 누적하지 않는다.
