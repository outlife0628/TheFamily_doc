**문서 ID:** SYS-02  
**버전:** Ver0.3  
**작성일:** 2026-10-21  
**상태:** 검토 · 권고 접근 채택 / Map Tool 사양 연계 예정 / 이동 UI 검토판 포함  
**승인자:** 사용자  
**선행 기준:** [SYS-01 승인본](01_Basic_System_UI_Ver0.4.2.md), [공용 UI 지침](reference/ui/docs/31_UI_Production_Guidelines_Ver0.8.1.md), [승인 콘셉트](reference/ui/docs/35_UI_Concept_Baseline_Ver0.8.1.md)

> **적용 기준:** 사용자는 본 문서의 권고안을 기본 접근으로 채택했다. 현재 프로젝트용 Map Tool은 별도로 개발 중이며, 완성 후 제공되는 실제 사양과 출력물을 기준으로 이동 시스템의 기술 세부·기획 데이터·UI 바인딩을 조정한다. 현재 UI 수치·맵 배치·기간·운임은 검토용이며 툴 지원이나 최종 게임 사양을 증명하지 않는다. SYS-02 전체의 최종 승인과 SYS-03 착수는 이번 목업 검토 후 별도로 진행한다.

## 1. 목적·범위·근거

### 1.1 플레이 목표

캐릭터가 실제 장소를 걷고, 문과 길을 찾고, 주민·사물과 상호작용하며, 필요한 일행과 물품을 가지고 새로운 장소로 이동한다. **이동은 목적지를 누르는 행정 절차만도, 매번 같은 길을 반복해서 걷는 작업만도 아니어야 한다.**

지역의 구조와 탐험이 먼저 성립하고, 차량·철도·비공정은 이후 이동 범위·시간·수송력을 넓히는 자산으로 연결한다. 직접 교역·실제 위치·화물은 유지하며 자동 매매·도착 보상형 파견으로 대체하지 않는다.

### 1.2 소유 범위

| 이 문서가 설계하는 것 | 다른 문서가 소유하는 것 |
|---|---|
| 마을·실내·야외·던전의 공간 연결, 직접 이동, 카메라·가림, 출입·현장 대상 접근 | 캐릭터 성장·기술 수치: SYS-03 |
| 이동 입력과 잠금, 파티의 현장 표현, 맵·미니맵·이동 HUD | 물품 사용·열쇠 소비·일반 상점: SYS-04 |
| 실제 위치·노선·출발·도착·중단·복귀, 운송자산 위치·배정·수송력 | 인카운터 발생 방식·전투 규칙·승패: SYS-05 |
| 현장 접근 검사와 상호작용 실행 요청 | 파티 영입·편성·리더 정책: SYS-06/07 |
| 이동에 필요한 비용·시간·자산의 연결 조건 | 매매·흥정·화물 인계의 경제 결과: SYS-08 |
| 맵 배치·출입구·이동 경로의 기획 데이터와 검사 | 사건 연출·퀘스트 목표 판정: SYS-09/10 |
| 비용·시간 소모 전 확인, 이동 후 UI 복귀 | 공통 달력·계산 순서: SYS-11 제안 / 실제 지출: SYS-13 제안 / 저장 파일: SYS-16 제안 |

SYS-02 안에서도 **A구간: 보행·탐험·현장 UI → B구간: 도시 간 이동 → C구간: 운송수단** 순으로 검토한다. 차량 세부를 먼저 결정하기 위해 보행 설계를 미루지 않는다. 다음 캐릭터 시스템을 동시에 새로 상세 작성하지 않는다.

### 1.3 근거와 제안의 구분

| 표시 | 뜻 |
|---|---|
| **유지** | 사용자 또는 선행 승인 문서에서 정한 기준 |
| **원작 근거** | 제공된 시나리오에 실제로 존재하는 장소·행동·사건. 조작 규칙의 승인을 뜻하지 않음 |
| **권고 방향 채택·세부 조정 가능** | 현재 문서의 권고 접근을 사용하되 툴 사양·실측·관련 시스템 검토 후 수치와 구현을 조정 |
| **연계 결정 대기** | 현재 단계만으로 확정할 수 없는 후속 소유 규칙 |

시드리아에는 시장·중앙역·산업지구·고아원·수로·지하 공병시설 등이 존재한다. Act 1 매물은 직접 방문·조사하며, 추가 조사에는 돈과 시간이 들고 랜덤 실패가 없다. Act 1 열차 사건에는 현장 복구·우회 판단·전투가 포함된다. **이 사실만으로 카메라 각도·맵 경계·이동속도·조우 확률까지 정해지지는 않는다.** 근거 위치는 [자료 기준](reference/Source_Basis.md)에 기록한다.


### 1.4 Map Tool과의 연계 기준

**이 프로젝트용 Map Tool이 개발 중이다.** 현재 단계에는 완성된 툴 버전, 출력 포맷, 샘플 맵, 좌표·콜리전·내비게이션·출입·미니맵 API의 최종 사양이 제공되지 않았다. 과거 기획·개념안 또는 본 목업을 실제 툴 사양으로 간주하지 않는다.

| 구분 | 지금 유지하는 것 | Tool 사양 확인 후 조정할 수 있는 것 |
|---|---|---|
| 플레이 구조 | 지역 내부 직접 탐험 + 도시 간 노선 여정, 실제 위치 보존 | 지역/청크의 분할·로딩·씬 연결 단위 |
| 공간·보행 | 3D 공간에 있는 2D 픽셀 캐릭터를 직접 이동 | 월드 단위·축·원점·스케일·충돌체·경사·통행층·속도 환산 |
| 카메라·표현 | 읽을 수 있는 길·대상, 승인된 절제된 HUD | 카메라 프로필·추적 범위·투영·가림·스프라이트 방향·그림자 |
| 출입·상호작용 | 한 대상·한 행동, 정상 진입/실패 복귀, 중복 실행 방지 | 앵커·포털·오브젝트 ID, 배치 방식·접근 검사·이벤트 바인딩 |
| 지도 | 지역 지도와 월드맵 분리, 공개된 정보만 표시 | 지도 베이크/출력 방식·월드→지도 변환·층 표현·아이콘 좌표 |
| 저장·재방문 | 문·조사·여정·화물·발견 상태 보존 | 툴 맵 개정과 영구 ID 대응, 저장 좌표 이전·안전 복귀 처리 |

기술 제약에 맞춘 조정은 허용하되 **파티 정원, 실제 위치·화물 소유, 시간·채무 엔딩, 원격 거래 금지와 같은 승인된 게임 규칙을 툴 편의로 바꾸지 않는다.** 그러한 영향이 생기면 변경 이유·대안·영향 범위를 사용자에게 제시하고 재승인을 받는다.

Map Tool이 특정 기능을 제공할 것이라고 단정하지 않는다. 지원 여부가 불명확한 기능은 `미확인`으로 두며 툴 출력 + 런타임 보완 + 연결 어댑터 중 책임을 사양 검토에서 배정한다. 예를 들어 미니맵 출력이 없다면 미니맵을 없애는 것이 아니라 별도 생성 여부를 검토한다.

#### 툴 사양 수령 후의 대조 절차

`툴 버전·명세·샘플 확보 → 기능 대응표 → 시범 맵 1개 연결 → 충돌/출입/가림/지도/저장 회귀 검사 → 변경 필요 항목 제안 → 승인 후 적용`

필수 확인 자료는 (1) 실제 출력 샘플과 포맷/버전, (2) 좌표·스케일·통행층, (3) 영구 맵/오브젝트/앵커 식별, (4) 충돌·이동 가능 영역, (5) 출입 연결과 카메라/가림, (6) 상호작용·이벤트 참조, (7) 공개 지도 데이터, (8) 맵 재출력 시 저장 참조 유지 방식이다. 이를 **정보 수령 체크리스트**로 사용하며 지금의 툴 구현 요구로 일방 지정하지 않는다.

[Map Tool 대응표](review/Map_Tool_Integration_Checklist.md)는 현재 모두 미확인이다. [목업 연계 계약](preview/map_adapter_review_contract.json)은 UI가 필요로 하는 의미 데이터의 검토 목록이지 최종 툴 API나 출력 스키마가 아니다.

현재 목업은 자체 시험 데이터를 사용하는 `ReviewMapAdapter` 역할을 코드로 시연한다. **Map Tool 출력물, Godot 씬, 실제 3D 물리·내비게이션 또는 툴 호환 검증 결과가 아니다.**

## 2. 유지하는 기준

| ID | 유지 기준 | 이동 설계에 미치는 영향 |
|---|---|---|
| MOV-F01 | 3D 맵 안의 2D 픽셀 아트 캐릭터 | 월드의 실제 위치·통행과 화면에 투영된 위치를 구분 |
| MOV-F02 | 최대 8개 공통 파티·각 최대 8명 | 표시 방식이 인원 정원이나 활동 권한을 바꾸지 않음 |
| MOV-F03 | 주요 인물이 있는 파티 간 직접 조작 전환 | 현재 조작 파티와 지도에서 조회하는 파티 구분 |
| MOV-F04 | 구성에 따른 상인 업무 자격 | 상인 없는 파티도 이동·탐험 가능. 상인이 있다고 원격 매매 가능해지는 것은 아님 |
| MOV-F05 | 행동 기반의 공통 날짜 | 메뉴·대화·직접 전투를 읽은 현실 시간에 달력·비용을 더하지 않음 |
| MOV-F06 | 개인·차량·화물의 실제 위치와 단일 소속 | 지도 조회나 파티 전환으로 다른 도시의 실물을 이동시키지 않음 |
| MOV-F07 | 도보·마차·스팀트럭·기차·비공정 성장 | 이동수단은 보유·구매·업그레이드·배정하는 자산. 차량 수송량과 파티 정원 별개 |
| MOV-F08 | 현지 구매·이동·현지 판매는 다른 행동 | 도착만으로 자동 판매·귀환·보상 수령을 수행하지 않음 |
| MOV-F09 | H-2 상황형 HUD / M-1 목록·상세 / 공용 행동 슬롯 | 현재 장소와 공개된 목표에 필요한 정보만 표시 |
| MOV-F10 | 지정 메인 사건에서 상환 차단·10년 제한 해제 동시 적용 | 이동 시간 진행 중 해당 사건과 유효한 종료 경계를 일관되게 처리 |
| MOV-F11 | 실제 완납 순간 해당 진행 종료 | 이동 중인 다른 파티나 미수령 보고 때문에 끝난 캠페인이 계속되지 않음 |

정확한 Act·달력 월일·같은 시점의 여러 결과 우선순위는 미정이다. 승인된 동시 전환의 두 효과만은 분리하지 않는다.

## 3. 공간 연결 구조 — MOV-D01

### 3.1 채택한 기본 접근

**지역 내부는 직접 탐험하고, **도시 간 장거리 이동은 월드맵에 표시된 도시를 목적지로 지정한 뒤 노선 여정으로 진행**한다.**

| 공간 | 현재 기본 접근 |
|---|---|
| 마을·실내 | 구역별 3D 공간에서 직접 보행·출입·대화·조사 |
| 야외·던전 | 탐험 현장의 갈림길·장치·층·출입을 직접 조작 |
| 도시 사이 | 월드맵 도시 표식 또는 동기화된 목록에서 목적지를 지정하고 파티·수단·경로를 확인한 뒤 실제 여정·시간 진행 |
| 정차·사건 | 필요한 지점에서 직접 현장/전투에 진입하고 남은 여정으로 복귀 |
| 목적지 | 실제 도착 후 현지 탐험·거래. 도착만으로 자동 판매하지 않음 |

노선 선택은 순간이동이나 자동 수익 파견이 아니다. 이동 중 파티·차량·화물은 여정 상태를 가진다. 비선택 파티도 같은 공통 날짜 축에서 활동하며, 자동전투와 자동매매 권한은 별개다.

현재 연결 접근은 사용자가 채택한 기본 기준이다. Map Tool의 지역/청크 출력 방식에 따라 기술 연결을 조정할 수 있으나, 도시 사이를 전부 직접 조작하는 연속 필드 구조로 바꾸는 것은 별도 범위 변경으로 검토한다.

### 3.2 지역과 제작 씬은 구분 — 권고 방향 채택·세부 조정 가능

`도시/광역 지역 → 플레이 구역 → 출입 연결 → 실내·탐험 구역`의 논리 구조를 사용한다. 예를 들어 ‘시장 구역’이 하나의 로드 단위여야 한다고 고정하지 않는다. 반대로 하나의 씬으로 만들었다고 시장과 실내를 같은 접근 권한으로 취급하지 않는다.

장소의 실제 크기·출입 위치·지도는 레벨 제작에서 정한다. 현재 문서에는 정식 도시 간 거리·선로 위치·새 지명을 만들어 넣지 않는다.

## 4. 공통 위치·이동 상태 — 권고 방향 채택·세부 조정 가능

### 4.1 위치의 세 구분

| 상태 | 보관할 내용 | 허용하지 않는 오해 |
|---|---|---|
| 현장에 있음 | 지역·구역·안전 위치·높이/통행층·방향·최근 출입점 | 화면에서 가까우면 다른 층의 물건도 닿는다고 판단 |
| 도시 사이 이동 중 | 출발·도착·노선·진행 구간·정차점·잔여 작업량 | 이동 중에도 출발 도시 또는 도착 도시 상점에서 거래 |
| 이동 사건으로 정차 | 원래 여정 참조 + 현재 현장 위치·복귀점 | 사건 맵에 들어가자 남은 운송·화물이 사라짐 |

화면상의 마커·미니맵 좌표는 위 실제 상태에서 계산하는 표시값이다. 파티 목록을 선택하거나 지도 목적지를 바꾸는 것은 실제 위치 변경이 아니다.

### 4.2 입력 소유와 중단

현장 이동·대화·메뉴·출입 전환·연출·전투·종료 상태를 구분한다. 한 시점에 직접 이동 입력을 받는 파티는 하나다. 이동 잠금은 이유를 함께 유지하며, 대화를 닫았어도 로딩·연출 등 다른 잠금이 남아 있으면 걷기 입력을 재개하지 않는다.

비선택 파티의 도시 간 활동은 공통 날짜 처리 대상이다. NPC가 화면에서 걷는 시각 연출과 회사의 날짜 진행은 다른 것이다. 미선택 파티까지 매 프레임 3D 현장 캐릭터로 시뮬레이션해야 한다는 요구는 두지 않는다.

## 5. 보행·달리기·파티의 현장 표현

### 5.1 기본 이동 — MOV-D02 / 권고 방향 채택·세부 조정 가능

| 항목 | 권고 설계 |
|---|---|
| 입력 | 키보드 방향 입력과 게임패드 스틱으로 직접 이동. 화면 기준 방향과 실제 이동 방향의 대응 유지 |
| 이동 형태 | 타일 한 칸 단위가 아닌 연속 이동. 걷기·달리기 제공 |
| 기본 속도 모드 | 기본 달리기 + 걷기 전환을 권고. 누르기/토글 설정은 입력 검토에서 정의 |
| 이동 비용 | 걷기·달리기 자체에 소모성 스태미나를 추가하지 않는 안. 달리기의 조우 영향은 SYS-05 결정 전 미적용 |
| 마우스 | 메뉴·지도·대상 정보 조작을 지원. 클릭 이동·자동 길 찾기는 기본안에 포함하지 않는 권고 |
| 점프·등반 | 자유 점프·수영·자유 등반은 기본안에 포함하지 않음. 필요한 사다리·단차 통과는 지정 연결 행동으로 검토 |
| 방향과 애니메이션 | 이동 방향 수와 스프라이트 애니메이션 방향 수를 분리. 4방향/8방향 아트·사선 표현은 아트 제작량과 함께 후속 선택 |

이동 결과는 위치·방향·실제 이동량이다. 충돌로 이동하지 못한 입력은 이동량을 늘리지 않는다. 사선 이동이 직선보다 빨라지지 않아야 하며, 스틱 중립으로 캐릭터가 흘러가지 않아야 한다. 정확한 속도·가속·입력 보정값은 미정이며 이번 문서에 시험값도 배포값처럼 넣지 않는다.

**UI·UX:** 걷기/달리기 모드의 짧은 안내는 입력 장치에 맞춰 표시한다. 평상시 속도 수치·스태미나 막대는 표시하지 않는다. 메뉴를 여는 순간 이동 입력을 해제하고, 닫을 때 새 결정 키가 조사·출입까지 연속 실행되지 않게 한다. 비용이 없는 보행마다 확인창을 띄우지 않는다.

**실패·저장:** 통행 불가 표면은 통과하지 않는다. 저장 가능 여부와 별개로 복원할 지역·안전 위치·방향을 정의한다. 잘못된 좌표 복원은 검증된 복귀점으로 처리하되 다른 도시 도착이나 위험 통과로 인정하지 않는 안을 사용한다. 구체 복구·저장 정책은 SYS-16과 연계한다.

### 5.2 현장 대표와 추종 — MOV-D04 / 권고 방향 채택·세부 조정 가능

현장 대표 스프라이트, 전투 리더, 상인 업무 담당은 다른 개념이다. 대표를 바꿨다고 멤버·리더 자격·교역 자격·직접 조작 가능 여부를 바꾸지 않는다.

권고는 **대표 1명 + 뒤따르는 최대 3명 표시**다. 나머지 구성원도 실제로 같은 파티에 있으며 8인 정원·전투 참가·현장 역할 검사는 전체 구성원을 기준으로 한다. 화면 표시 4명이 전투 출전 4명 제한을 뜻하지 않는다. 대안은 8명 전원 추종 또는 대표 1명만 표시다. 이번 UI 검토판에서는 대표+추종 3명 표현을 사용한다. 최종 추종 수·추종 경로는 Tool 사양과 가독성 검증 후 확정하며 실제 8인 정원을 줄이지 않는다.

추종자는 대표를 물리적으로 밀거나 문을 막지 않는다. 연출용 재정렬은 같은 현장 안의 시각 처리이며 다른 파티 인물을 불러오는 기능이 아니다. 멀리 뒤처진 추종자가 있다고 문 통과를 반복 대기시키거나, 숨겨진 문을 추종자가 먼저 열어서는 안 된다. 출입·지역 발견·조우의 중복 판정을 막도록 대표의 실제 이동을 주 판정 입력으로 삼는 안이다.

**UI·UX:** 대표 변경은 지역에서 허용될 때 소형 목록으로 처리하고, 상태창에서는 실제 1~8명을 조회한다. 다른 도시의 파티원은 후보에 포함하지 않는다. 같은 파티 브람의 전문 행동을 사용하기 위해 단순히 앞에 세우는 추가 조작은 요구하지 않는 안을 권고한다.

## 6. 3D 공간·카메라·가림

### 6.1 카메라 — MOV-D03 / 권고 방향 채택·세부 조정 가능

**구역별 고정 시점 + 캐릭터 추적 + 기획된 전환**을 권고한다. 플레이어의 자유 회전은 기본안에서 제외하고, 길과 상호작용 대상이 잘 읽히도록 구역별 시점을 배치한다. 대안은 제한 회전 또는 자유 회전이다. 투영 방식·각도·거리·심도 효과는 이 선택만으로 확정하지 않는다.

카메라는 구역의 경계를 넘어 미공개 방을 먼저 보여주지 않아야 한다. 연출이 끝나면 원래 탐험 시점과 입력 상태로 돌아온다. 플레이어가 이동 중인 동안 자동 회전으로 조작 방향이 갑자기 뒤집히지 않도록 전환 구간·입력 유지 방식은 실제 배치에서 검토한다.

**UI·UX:** 미니맵의 방향은 한 가지 규칙으로 유지하고 현재 캐릭터 방향을 구분한다. 카메라가 이동해도 공용 메뉴·버튼의 위치는 바뀌지 않는다. 화면 흔들기·강한 심도·모션 블러를 통행 판단에 필수적인 정보로 사용하지 않는다.

### 6.2 높이·충돌·통행

캐릭터는 허용된 지면·경사로·계단·연결구간을 이동한다. 화면상 겹치는 다리 위와 다리 아래는 별개의 통행층으로 취급한다. 유효 대상 판정에는 실제 거리뿐 아니라 같은 접근 층·경로·사이 장애물을 사용한다. 가까워 보이는 벽 너머 NPC에게 말을 걸지 않는다.

사다리·승강기·일방 통로는 출발·도착 지점과 사용 조건을 가진 연결물로 제안한다. 별도 버튼으로 자유롭게 점프할 수 있다는 뜻은 아니다. 위험 지형의 접촉 피해·낙사·지속 독은 승인된 효과 정책이 없으면 임의 추가하지 않는다.

**UI·UX:** 사용할 수 있는 연결물에 접근하면 `올라가기`, `승강기 사용` 등 실제 행동을 표시한다. 잠겼다면 플레이어에게 공개 가능한 사유를 알려준다. 이동키를 눌렀다는 이유만으로 위험한 낙하를 확정하지 않는다. 경사·계단이 장식인지 통행 가능한지 환경 아트와 상호작용 표시가 일치해야 한다.

### 6.3 가림 처리

전경·지붕·벽이 대표와 현재 상호작용 대상을 지속적으로 가릴 때 지정된 가림 대상을 축약/반투명/단면 표시하는 안을 권고한다. **시각적으로 사라진 벽의 충돌·문 잠금은 그대로** 유지한다. 가림 처리가 미발견 방·숨은 증거·반대편 NPC까지 보여주는 투시가 되지 않게 저작한다.

2D 캐릭터의 화면상 위치와 발이 닿는 지면, 그림자·가림 순서가 맞아야 한다. 스프라이트를 카메라에 맞추는 방식, 조명·그림자·픽셀 선명도는 별도 아트/기술 검증 항목이며 이번 문서는 엔진 해결법을 확정하지 않는다.

**검수 장면:** 시장 차양 뒤, 좁은 실내 문, 다리 위/아래, 계단, 고아원 지하 입구. 배경이 3D인 것과 필수 정보가 가려져도 되는 것은 별개다.

## 7. 출입·구역 전환

### 7.1 흐름 — 권고 방향 채택·세부 조정 가능

`출입점 접근 → 공개 조건·도착점 검사 → 필요할 때 행동 확정 → 이동 입력 잠금 → 목적지 준비 → 위치 전환 확정 → 안전 위치에 배치 → 지역·목표 안내 → 입력 재개`

| 항목 | 설계 |
|---|---|
| 일반 문 | 행동 안내를 보고 결정 입력으로 출입하는 안. 비용이 없으면 추가 확인창 없음 |
| 열린 길·구역 경계 | 기획된 경계를 통과하면 연결. 월드 경계 표시와 카메라 연출로 전달 |
| 잠금·사건 차단 | 해당 아이템/이벤트 조건을 검사. ‘조건 없음’과 ‘정책 미정’은 구분 |
| 도착점 | 지역 ID와 출입점 ID로 지정. 닫힌 문 안이나 장애물 속을 기본 위치로 쓰지 않음 |
| 재진입 방지 | 도착 배치를 출구 판정과 분리하고, 같은 입력으로 역방향 전환이 반복되지 않게 함 |
| 로드 실패 | 원래 확정 상태와 위치를 유지/복구하며 이유 표시. 열쇠·돈·시간만 소모된 상태를 남기지 않는 안 |

문을 여러 번 눌렀다고 출입 요청을 쌓지 않는다. 정상 완료 시 지역 도착 사실을 이벤트·퀘스트 시스템에 전달하지만, 그 사실만으로 모든 방문 퀘스트를 직접 완료하지 않는다.

**UI·UX:** H-2의 대상 표식과 공용 로딩/오류 레이어를 사용한다. 읽는 설명·확인창이 있으면 배경 걷기를 잠근다. 정확한 로딩 진행률을 알 수 없으면 임의의 퍼센트를 만들지 않는다. 다시 시도·이전으로 등 행동은 동일한 공용 슬롯을 사용한다.

### 7.2 원작 장소의 연결 사례

‘고아원의 지하 보관실’과 ‘더 깊은 지하 구조’는 같은 말로 합치지 않는다. Act 2에서는 열쇠로 들어갈 전쟁기 보관실이 있고 더 깊은 구조는 이후 재조사의 공간적 복선이다. 이 사실은 **층·출입·공개 조건을 따로 관리해야 할 근거**이며, 특정 맵 분할이나 보이지 않는 후속 층 아이콘을 지금 배치하는 승인은 아니다. [S-04]

## 8. 현장 상호작용·탐험

### 8.1 한 대상과 한 입력 — 권고 방향 채택·세부 조정 가능

후보가 여럿일 때는 접근 가능 조건을 먼저 검사하고, 거리·바라보는 방향·작가가 정한 우선순위로 현재 대상 하나를 정한다. 모든 대상에게 아이콘을 겹쳐 띄우지 않는다. 겹친 후보의 수동 전환 입력을 제공하는 방향을 권고하며, 구체 키는 입력 설계에서 정한다.

`대상 강조 → 행동명 확인 → 실행 입력 → 조건 재검사 → 소유 시스템 호출 → 결과 표시 → 원래 현장 복귀`

| 대상 | 이동 시스템의 책임 | 결과를 정하는 곳 | 같은 기능의 UI |
|---|---|---|---|
| NPC | 같은 현장·접근·현재 대화 가능 검사 | SYS-09 대화/이벤트 | 가까운 한 대상에 `대화`, 이후 D-1 |
| 상점·길드·역 | 현재 파티와 장소의 이용 접근 전달 | 해당 콘텐츠 시스템 | 동일한 상점·의뢰·이동 화면 재사용 |
| 조사물 | 접근 가능·조사 진행 중 중복 입력 검사 | SYS-09/10/15 | 짧은 조사 안내 → 결과·새 목표를 공용 알림에 표시 |
| 채집·보관물 | 위치와 오브젝트 상태 전달 | SYS-04 획득·용량·소유 검사 | 획득 내용과 가방/중요품 분류 안내 |
| 장치·수리 | 실제 사용 위치·필요 구성원을 현장에서 조회 | SYS-03 역할, SYS-09 작업 효과 | 필요한 인물·비용·시간을 공용 상세로 확인 |
| 출입구 | 접근·연결·도착점 검증 | SYS-02 | 행동 안내 또는 공개된 차단 사유 |

같은 파티에 필요한 인물이 있어도 그 인물이 현재 행동 가능한지에 대한 상세는 캐릭터·이벤트 정책을 따른다. **상인 역할만 있으면 모든 전문 행동을 할 수 있는 것은 아니다.** 다른 파티의 인물·사업 직원은 자동으로 현장 멤버가 되지 않는다.

### 8.2 시간·비용이 있는 조사

원작의 추가 매물 조사는 소액 비용과 시간을 지불하면 숨은 장점을 확정 발견하며, 계약 후에도 발견할 수 있다. 이 사례에 임의 성공확률·자동 실패를 추가하지 않는다. [S-03]

**통합 동선 제안:** 대상 조사 → 공개된 기본 정보 → `추가 조사` 선택 → 비용·시간·필요 인물과 실행 결과 범위를 한 번 확인 → 승인된 작업 수행 → 조사 결과 반영 → 현장 복귀. 실제 정보 공개·돈·시간 차감은 각 소유 시스템의 한 처리 결과로 연결한다.

추가 조사 버튼이 사라지거나 이동하는 대신 같은 보조/주 행동 슬롯 안에서 상태와 이름을 바꾼다. 완료 기록을 다시 읽는 데 돈·시간을 재차 요구하지 않는다. 미공개 보상의 정체나 사건의 배후를 버튼 잠금 사유로 먼저 노출하지 않는다.

### 8.3 지역 상태와 재방문

문 개방, 장치 작동, 조사 기록, 중요 물품 확보, 사건 정리 상태를 개체 ID로 보존한다. 지도 재열람·같은 문 출입으로 원상복구하지 않는다. 일반 자원·적의 재생성은 SYS-04/05/11과 함께 별도로 정한다.

기본안에서 지역 보행에 운영 날짜를 직접 부과하지 않는다면, 반복 보상이 무료로 무한 재생되는 구조가 되지 않는지 별도 검토한다. 그렇다고 이동 문서가 원작의 반복 생계 수익에 임의 상한을 추가하지는 않는다. 유한 조사물의 1회성 상태와 반복 의뢰의 승인된 시간/재수락 조건을 구분한다.

## 9. 지도·목표 안내와 H-2 HUD

### 9.1 지도는 두 가지 질문에 답한다 — 권고 방향 채택·세부 조정 가능

| 지도 | 목적 | 표시 내용 | 실행하지 않는 것 |
|---|---|---|---|
| 지역 지도 | 지금 있는 장소에서 어디로 걸어가야 하는가 | 현재 위치·통행층·알게 된 길·시설·출입구·공개된 목표 | 지도 클릭만으로 캐릭터 이동·방 열기 |
| 월드맵(도시·노선) | 어느 지역으로 어떤 방식으로 갈 것인가 | 알려진 도시·노선·현재 파티 위치·노선 조건 | 조회 도시로 순간이동·원격 거래 |

‘알고 있는 장소’, ‘방문한 장소’, ‘들어갈 수 있는 장소’를 별도 상태로 구분한다. 안내받아 이름만 아는 도시가 있을 수 있고, 방문했던 곳도 사건으로 막힐 수 있다. 정확한 지도 공개 정책은 MOV-D06에서 결정한다.

권고는 **도시의 공개된 공공시설은 안내 정보로 제공하고, 던전 내부는 탐험/정보 획득에 따라 공개**하는 것이다. 숨은 증거·후속 구역·발견 전 출구를 지도나 검색 목록이 먼저 알려주지 않는다. 모든 시설 발견을 강제로 클릭하게 하는 방식과 모든 숨은 지점 자동 공개를 모두 피한다.

### 9.2 같은 기능의 UI·UX

H-2의 소형 미니맵은 방향 파악을 맡고, 확대 지도는 M-1의 위치 목록·지도 상세를 이용한다. 목표 목록은 SYS-10에서 공개된 한 현재 행동을 받아 표시한다. **지도 선택·목표 추적은 실제 방문·수락·완료가 아니다.**

| H-2 영역 | 표시/숨김 조건 | 누를 때의 행동 |
|---|---|---|
| 좌상단 지역명 | 진입 시 표시 후 축약 | 필요 시 지역 정보 |
| 우상단 소형 미니맵 | 사용자의 표시 설정을 보존 | 지역 지도 열기 |
| 미니맵 아래 목표 1개 | 현재 공개된 추적 행동 1~2줄 | 해당 일지/알려진 장소 확인 |
| 대상 근처 표식 | 현재 접근 가능한 한 대상 | 실제 의미 입력으로 상호작용 |
| 하단 왼쪽 문제 요약 | 상태 변화 알림 후 미해결 문제를 축약 유지 | 현재 파티 상태 보기 |
| 하단 오른쪽 입력 안내 | 입력 장치·사용자 설정에 대응 | 지도·메뉴의 의미 입력 표시 |

일반 날짜·지갑·화물·다른 파티의 상태는 필드 상시 표시에서 제외한다. 시간 제한 경고 등 중요한 문제는 알림과 다시 볼 상세 경로를 제공하며 해결되지 않았는데 기록까지 지우지 않는다. 기한 해제 사건 후에는 그 기한의 경고를 제거하되 다른 의뢰의 마감은 유지한다.

3D 배경과 월드 표식이 겹칠 때 HUD 전체를 임의 이동하지 않는다. 대상 표식의 가림 회피·화면 경계 안 보정은 정의된 영역 안에서 처리한다. 큰 글씨에서는 목표를 말줄임해 목적지를 잃게 하지 않고 폭·줄바꿈·상세 접근을 조정한다. 공개 정보만으로 위치를 모르겠다면 정확한 마커 대신 알려진 탐색 범위를 전달한다.

**행동 슬롯:** 지도/목록의 주 행동은 하단 오른쪽, 닫기·이전은 그 왼쪽, 층/범례 등 보조는 하단 왼쪽에 둔다. 콘텐츠가 길어져도 버튼은 스크롤되지 않는다. 지역 지도에서 주 행동이 필요 없으면 해당 슬롯을 비워도 닫기가 오른쪽 끝으로 이동하지 않는다.

### 9.3 월드맵의 역할과 자료

**도시 간 이동의 기본 진입 화면은 월드맵이다.** 메뉴에서 표 형태의 노선 목록만 보여주는 것으로 대체하지 않는다. 플레이어는 지리 위의 현재 위치와 목적지·경로를 읽고 여행을 결정한다.

사용자 제공 `더패밀리_월드맵.png`(1511×1041)를 지도 배경으로 사용한다. [원본 보관 파일](preview/assets/world_map_source.png)은 업로드와 동일한 바이트로 보존한다. 대륙·섬·강·산맥의 구성을 생성 시안으로 다시 그리거나 화면비에 맞춰 늘리지 않는다. 지도 외곽의 그림 프레임은 원본 아트의 일부이며, 다른 창·버튼에 같은 장식 프레임을 반복하지 않는다.

이 이미지는 **월드 지리 구성안**이다. 확정된 도시 좌표·국경·선로·도로망·거리·시세 데이터를 포함한다고 간주하지 않는다. 목업의 시드리아 위치도 검토 배치다. 시드리아는 중립 공동도시로 설명하고 왕도·수도로 바꾸지 않는다. 인간 도시·드워프 도시·엘프 도시 표기는 임시 분류명이며 정식 이름과 위치는 별도 승인한다.

### 9.4 지도·목록·여행 계획의 한 상태

| 정보/행동 | 시스템 규칙 | UI·UX |
|---|---|---|
| 현재 위치 | 실제 파티의 현지 도시 또는 이동 구간에서 계산 | 청색 방향 표식, 도시명, 여정 중일 때 실제 경과 위치 |
| 목적지 선택 | 공개된 도시 ID만 선택. 자금·파티 위치·화물·날짜 불변 | 지도 표식 클릭과 목적지 목록·방향키 선택을 동기화 |
| 선택 경로 | 출발 도시와 목적지의 연결 정보로 계산. 화면상 직선·그림 속 길을 이동 가능 판정으로 사용하지 않음 | 선택 노선을 강조, 필요 시 경유 도시 표시 |
| 알려진 미개방 경로 | 정보를 아는 것과 이용 가능한 것을 구분 | 선택·사유 열람은 가능, 출발 불가 및 이유 표시 |
| 미공개 장소·노선 | 공개 조건 미달 정보는 표시 계층에 전달하지 않음 | 숨은 장소를 빈 라벨·검색 결과·잠금 사유로 예고하지 않음 |
| 확대·축소·이동 | 표시 변환만 변경 | 휠/버튼/+/−, 드래그/Shift+방향키, 전체 보기·현재 위치 |
| 출발 준비 | 현재 선택한 목적지·수단·위치·비용·적재를 검사 | 한 번의 공용 확인창에서 기간·지출·잔금·화물 확인 |
| 출발 확정 | 재검사 후 여정 생성. 시간 진행과 구분 | 취소는 무변경, 확정은 여정 화면으로 연결 |
| 정차·재개·도착 | 기존 여정·화물·잔여 시간 보존. 도착 시 한 번 위치 변경 | 지도상의 이동 표식 + 상태 요약. 도착은 자동 매매가 아님 |

**선택과 실행은 두 단계다.** 지도 표식/목록을 고르는 것이 목적지 선택이며, 동일한 선택을 다시 승인하는 ‘목적지 지정’ 버튼을 중복 배치하지 않는다. 이후 `출발 준비 → 취소/출발 확정`으로 비용이 있는 실행을 구분한다. 정상 지역 탐험에서는 월드맵을 열어도 보행 위치를 이동시키지 않는다.

목업에서 한 파티·다섯 공개 장소·노선 그래프로 동작을 검토한다. 실제 다중 경로 최적화·우회·통행 허가와 8개 파티 병행 처리의 완성을 뜻하지 않는다.

### 9.5 표시 좌표와 Map Tool의 경계

지도 표식은 원본 이미지 기준 정규화 좌표 `(u,v)`로 배치하는 **검토 데이터**다. 이는 3D 맵의 월드 좌표·길이 단위가 아니다. 확대·패닝에서 지도·표식·노선을 함께 변환하고, 선택·라벨의 화면 표시만 계산한다.

월드맵 배경과 도시/노선 데이터, 지역 Map Tool 출력, 현재 파티 상태는 서로 분리한다. Tool에서 확인할 연결은 `도시/지역 영구 ID → 실제 플레이 맵 → 출발/도착 앵커`다. Tool이 월드맵·노선 편집·미니맵 생성을 이미 지원한다고 가정하지 않는다. 지원이 없으면 런타임·별도 기획 데이터·어댑터의 책임을 검토하고 게임 규칙은 사용자 검토 없이 바꾸지 않는다.

### 9.6 월드맵 공용 부품과 접근성

`MapPane + DestinationList + RouteSummary + ActionDock`를 조합한다. 미니맵·지역 지도·월드맵의 역할은 다르지만 글자·선택·버튼·취소 규칙은 공유한다. 현재 위치와 선택 목적지는 색뿐 아니라 화살표/마름모와 문구로 구분한다.

100% 글씨에서는 지도 옆 목록과 선택 상세를 함께 표시한다. 125/150%에서는 같은 우측 영역의 `목적지 / 여행 계획` 탭으로 읽기 단계를 나누며, 장소의 긴 설명은 공용 상세창으로 접근한다. 비용·기간·적재·출발 불가 이유와 주/취소 버튼은 계속 접근 가능해야 한다. 150% 지도 라벨은 현재/선택 장소를 우선하고, 모든 공개 장소 이름은 목록에서 읽는다.

일반 화면에서 확인·출발은 하단 오른쪽, 이전은 그 왼쪽에 고정한다. 선택 행·비교·확인 취소 뒤에는 대상·포커스·목록 스크롤을 복원한다. 도시가 화면 밖에 있을 때 키보드로 선택하면 보이는 범위로 지도 표시를 조정한다. 이것은 실제 이동이 아니다.

## 10. 도시 간 이동 — 채택 접근의 상세 설계

> 지역 탐험 + 노선 여정의 채택 방향을 구체화한다. 시간·요금·정산 순서의 상세는 후속 소유 시스템과 함께 검토하며, HTML의 시험값을 정식 값으로 사용하지 않는다.

### 10.1 준비와 출발

`실제 파티 확인 → 월드맵 열기 → 도시 표식/목록에서 목적지 지정 → 현재 수단·적재·공개 경로·비용·기간 확인 → 출발 확정 → 여정 진행 → 사건/정차 또는 도착 → 현지 탐험`

출발 전에 실제 파티와 위치, 리더 조건, 다른 활동의 점유, 운송자산 배정, 통행·목적지 접근, 적재 한도, 필요한 비용을 검사한다. 노선 조회는 무료 정보 열람이며 자금·위치를 바꾸지 않는다. 확인 이후 조건이 달라졌으면 출발 시 다시 검사한다.

**권고 방향 채택·세부 조정 가능:** 여러 파티에 먼저 출발을 지시한 뒤 공통 시간을 진행할 수 있도록 ‘출발 확정’과 ‘여정 시간 진행’을 구분한다. 출발 확정은 유효한 여정을 만들고 필요한 자산을 묶는다. 정확한 운임 차감/예약 시점은 SYS-13과 함께 정하며 같은 돈을 예약과 지급으로 두 번 차감하지 않는다.

UI는 같은 파티의 지도에서 목적지 목록·현재 위치·선택 노선·이동수단·적재·소요일·예상 도착·실제 지출을 함께 보여준다. `출발`은 고정 주 행동이고 `이전`은 바로 왼쪽이다. 실패하면 공개 가능한 사유와 해결 경로를 표시하며, 가격·기간 정책이 미정인 상태를 0원·즉시 도착으로 표시하지 않는다.

### 10.2 진행·정차·도착

| 상태 | 시스템 처리 제안 | 플레이어에게 보여줄 것 |
|---|---|---|
| 준비 중 | 견적·경로를 검토, 상태 변경 없음 | 현재 위치·선택 목적지·확정 전 영향 |
| 이동 중 | 노선 구간과 경과·잔여 시간을 보존 | 실제 ‘이동 중’, 출발/도착지·다음 정차/공개된 사건 |
| 사건 중단 | 해당 위치에서 진행을 멈추고 사건 ID·미처리 여정을 보존 | 정차 이유·현장 진입 또는 필요한 선택 |
| 재개 가능 | 사건 결과를 한 번 적용하고 남은 여정 유지 | 남은 기간·변경 비용·재개/허용된 대안 |
| 도착 | 목적지 진입 조건과 도착점을 확인, 여정 완료 | 도착 알림과 실제 위치 갱신 |
| 실패·중지 | 이미 이동한 거리·발생 비용은 기록 | 가능한 복구/중지 사유. 즉시 출발지 환원은 하지 않음 |

도착 시 한 번만 위치·활동 결과를 반영한다. 직접 조작 파티는 해당 도시의 입구·역·항만 등 이동수단에 맞는 현장으로 연결한다. 상품은 그 파티의 화물로 남고 자동 판매하지 않는다. 도착 보고를 안 읽어도 도착은 적용된다.

### 10.3 여정의 조작 범위 — MOV-D08 / 결정 대기

A안의 기본 권고는 **목적지·경로·정차 선택은 플레이어가 하고, 일반 운행 진행은 시스템이 처리**하는 것이다. 인카운터와 의미 있는 정차 현장에서는 직접 탐험/전투로 들어간다. 파견 버튼을 누르고 돈만 받는 콘텐츠가 아니다.

여정 취소·우회·중도 하차는 실제 정차/전환 가능한 지점과 비용 정책이 필요하다. 기본 초안은 **합법적인 정차 지점에서 경로를 변경하고, 이동 중 즉시 출발지로 돌아가는 취소는 제공하지 않는 안**을 권고한다. 소유차량의 자유 경로와 공공 교통 이용권, 노선 발견 방식, 재방문 빠른 이동은 추가 결정 전 자동 도입하지 않는다.

열차 사건에 등장하는 공공/의뢰 운송과 플레이어가 소유한 기차는 구별한다. 원작 열차 사건에 참가하기 위해 개인 기관차를 소유해야 한다는 조건을 추가하지 않는다.

### 10.4 사건·전투 복귀

여정 도중 현장에 진입할 때는 원래 여정·파티·화물 위치·처리한 사건 순번·복귀 지점을 보관한다. 직접 전투 또는 결과만 보고하는 자동전투는 SYS-05/06 규칙을 따른다. 무슨 방식으로 조우할지, 어떤 피해·보상을 받을지는 이 문서에서 정하지 않는다.

전투 종료 뒤 지역 위치·여정의 남은 구간을 복원하며, 도주·패배·이야기 진행의 결과를 무조건 목적지 도착으로 바꾸지 않는다. 조사나 전투에 운영 날짜 비용이 있다면 명시된 활동 비용만 사용하고, 같은 노선 소요일을 두 번 붙이지 않는다.

## 11. 운송수단과 실내 탐험의 연결

### 11.1 자산과 이동 역할

**유지:** 도보·보부상은 기본 방식, 마차·스팀트럭·기차·비공정은 구매·개조·배정하는 자산이다. 한 파티에 차량을 몇 개 둘지, 화차·기체 편성을 어떻게 할지는 아직 미정이다.

| 방식 | 현재 유지할 의미 | 상세 설계 경계 |
|---|---|---|
| 도보·보부상 | 차량 없이 인물과 휴대 화물로 이동 | 인물별/파티별 수송량·보행 여정 속도 미정 |
| 마차·스팀트럭 | 육상 교역 규모와 운송 능력을 확장 | 대수·허용 도로·수리·연료·견인·운전 표현 미정 |
| 기차 | 철도 노선과 큰 화물 운송에 연결 | 공공 철도 이용과 소유 열차, 기관차/화차 조합·역 접근 미정 |
| 비공정 | 항로 접근과 장거리/특수 노선 운송 | 항만·이착륙 장소·직접 조종 여부·승무원·기체 상세 미정 |

모든 수단에 필수 연료 계기·마모도·승무원 작업표를 먼저 만들지 않는다. 이동수단의 수송량·경로·비용·기간 변화는 보여주되 현실 정비 시뮬레이션을 자동으로 추가하지 않는다.

### 11.2 구매·배정·개조 UI 연결

이동자산 목록과 후보 비교는 M-1의 목록·상세/비교·수량·공용 확인을 사용한다. 구매는 소유 개체 생성, 배정은 실제 이용 파티 지정, 개조는 해당 개체의 성능 변화다. 현지 판매처/개조처와 경영의 운송수단 탭은 같은 상태를 보여준다.

후보에서 수송량·사용 가능 경로·가격·조건·현재 자산 대비 변화를 읽고 단일 주 행동으로 확정한다. 예산·위치·점유·해금·적재 초과 등의 실패 사유를 제공한다. 다른 파티가 사용 중인 차량을 임의 해제하지 않으며, 더 작은 수단으로 바꾸기 위해 화물을 자동 폐기하지 않는다. 차량 수와 개조 구조를 정하기 전 세부 슬롯 목업은 만들지 않는다.

### 11.3 하차·접근과 화물 — MOV-D07 / 권고 방향 채택·세부 조정 가능

도시에 도착한 큰 운송수단은 역·항만·주차 지점 등에 두고 일행이 건물 안을 걷는 구성을 권고한다. 차량이 상점 내부나 던전 계단까지 캐릭터를 따라다니지 않는다.

**파티가 같은 도시의 실내에 들어가도 화물을 인물 개인 가방으로 자동 이전하지 않는다.** 운송자산과 화물의 보관 위치를 유지한다. 도시에 도착했다는 광역 정보와 인물이 건물 안에 있다는 세부 위치를 구분한다. 실제 현지 거래에서 차량 화물에 접근할 수 있는 범위·자동 적재/하역은 SYS-08과 연결해 정한다. 다른 도시나 격리된 현장에서 차량 짐을 원격 판매하는 허용으로 해석하지 않는다.

같은 도시의 정상 하역·적재는 반복 승인 버튼 없이 처리한다는 기존 방향은 유지한다. 다만 차량을 떠나 던전 깊이 가져갈 수 있는 물품·화물의 종류와 용량은 아직 미정이다. ‘필드 물품 휴대’와 ‘교역 화물 수송’을 구분하는 데 필요한 규칙만 선행 협의하며, 새 생존·무게 페널티를 임의로 부과하지 않는다.

## 12. 이동·탐험과 공통 시간

### 12.1 MOV-D05 — 권고 방향 채택·세부 조정 가능

**권고: 지역 안에서 길을 찾고 대화를 읽는 보행 시간은 공통 달력으로 환산하지 않고, 도시 간 여정·명시적인 조사/작업·휴식 등에 승인된 시간 비용을 부여한다.** 이는 국지 탐험 비용에 대한 새 제안이다. 이전에 확정된 것은 현실 메뉴·대화·전투 시간이 운영 날짜를 진행시키지 않는다는 공통 원칙이다.

| 행동 | 시간 처리 제안 | UI |
|---|---|---|
| 같은 마을/실내 보행·메뉴 열람 | 운영 날짜 직접 증가 없음 | 실시간 시계·매 걸음 날짜 경고 없음 |
| 국지 야외·던전에서 길 찾기 | 현실 소요시간을 일수로 환산하지 않음 | 위험은 장소·사건으로 안내 |
| 시간 비용이 있는 조사·현장 작업 | 사전 공개한 비용과 기간을 소유 시스템에서 반영 | 실행 전 공용 상세/영향 요약 |
| 도시 간 여정 | 승인된 노선 시간 진행. 여러 활동 병행 | 현재·예상 도착·중단 상태 |
| 현장/여정의 전투 | 전투 중 현실 시간은 운영 날짜가 아님 | 전투 복귀 후 승인된 지연이 있으면 설명 |
| 쉬기·대기 | 명시한 기간 진행 | 효과·기간·유효 기한을 확인 |

던전 탐험에 하루 등 단위 비용을 붙일지, 입장/탐험 단계/특정 작업 중 어디에서 부과할지는 별도 선택이 필요하다. 이번 초안으로 탐험 전체의 경제 시간 비용이 영구적으로 0이라고 확정하지 않는다. 보행마다 몰래 날짜를 진행시키거나 후속 일괄 정산으로 예고하지 않은 시간을 차감하지 않는다.

### 12.2 종료·정산 경계

**유지:** 유효한 E.C.5010 기한까지 미상환이면 채무 불이행 게임오버다. 지정 메인 사건에서 상환 차단과 10년 제한 해제가 함께 적용된 뒤에는 그 기한으로 종료하지 않는다. 주인공 사망·주요 시나리오 실패는 별도다.

긴 이동·대기는 중요한 사건·정산·기한의 경계를 넘기기 전에 해당 경계의 규칙을 확인해야 한다. 목적지 도착을 먼저 적용한 뒤 이전 시점의 사망·엔딩을 뒤늦게 처리하지 않는다. 단, 같은 시점에 기한·전환 사건·소득·마지막 상환이 충돌하는 우선순위는 SYS-11/09/13과 선행 협의한다. 사용자 승인 없이 ‘이벤트가 항상 기한보다 우선’ 같은 규칙을 만들지 않는다.

정책 미정 상태는 정식 이동 실행을 완료했다고 표시할 수 없다. 관련 없는 보행·지도·정보 UI를 검토하는 것은 가능하다. 기한 해제는 공통 날짜·급여·이동을 정지시키지 않는다.

### 13.1 정의와 실행 상태

필드 이름과 자료형은 검토 제안이다. **새 데이터 양식과 실제 Excel 변환기를 이번에 제작한 것은 아니다.**

### 13.2 기획자 작성 동선

노선·게임 조건 등 기획 데이터는 Excel 기반 방침을 유지한다. 실제 3D 위치·출입 앵커·카메라 범위는 Map Tool의 저작·출력 방식과 대조해 영구 ID로 연결한다. 같은 공간 데이터를 Excel과 Map Tool 양쪽에서 수동으로 중복 관리하지 않는다. 대량의 3D 좌표를 사람이 Excel에 반복 입력해야만 맵을 편집할 수 있는 구조는 피한다.

기획자는 `지역 정의 → 구역/앵커 배치 → 출입 연결 → 조건/행동 참조 → 공개 정보 설정 → 검사 → 직접 왕복/복귀 테스트` 순서로 작업한다. 현재 개발 중인 Map Tool의 실제 작성·출력 동선과 대조해 이 작업 절차를 조정한다. 이 문서의 필드와 절차를 툴의 이미 구현된 사양으로 간주하지 않는다.

미정 기한·시간·비용 참조는 0이나 기본값으로 조용히 대체하지 않는다. 검토용 연결은 표시하고, 정식 배포 전 필요한 참조가 모두 해결되었는지 검사한다. 겉으로 보이는 이름은 변경 가능하지만 ID는 저장 참조가 유지되도록 관리한다.

### 13.3 전달할 사실과 책임

| 사실/요청 | 수신 시스템 | 주의 |

### 13.4 저장·재개·오류

저장이 허용된 시점의 지역/여정, 처리한 문·조사·사건, 소유 차량·화물 위치, HUD 설정을 복원한다. 도착·전투 복귀·상호작용 결과를 이미 처리했다면 다시 지급하거나 시간을 차감하지 않는다.

출입 중간 저장 허용 여부는 SYS-16 결정 대상이다. 허용한다면 전환 전 또는 전환 후 하나의 일관된 상태로 복원할 수 있어야 한다. 그렇지 않으면 중간 저장을 막거나 완결된 시점으로 요청을 넘긴다. 맵 참조가 손상됐다고 임의 목적지로 이동·완료시키지 않는다.

## 16. 현재 산출물과 검토 범위

이 문서는 이동 시스템과 필요한 UI를 같은 기능 아래 정의한다. 현재 [단일 HTML 목업](preview/TheFamily_Movement_UI_Ver0.3.html)과 편집 소스, 화면 캡처를 제공한다. 마을·실내·야외·던전의 시험 배치, 보행·출입·조사, 지역 지도/첨부 월드맵의 목적지 지정, 수단 선택, 출발·정차·재개·도착을 검토한다.

**미제작·미검증:** 실제 Map Tool 연결, Godot 게임 코드·3D 물리·높이/층 내비게이션·맵 스트리밍·게임패드, 정식 캐릭터/맵 아트, 전투·퀘스트·교역·차량 구매/개조·기한 엔딩의 전체 계산.

현재 §14의 엔진 인수시험은 미실행이다. HTML의 모델·브라우저 검사는 별도 [검증 보고서](qa/VALIDATION_REPORT.md)에 실제 수행한 것만 기록한다. 브라우저에서 사각 장애물 이동을 확인했다고 Godot 충돌 검사를 통과한 것으로 간주하지 않는다.

사용자는 구체 UI의 정보량·입력 동선·버튼 고정·큰 글씨·여정 흐름을 검토한다. Map Tool 완성을 기다리기 전에도 이 UI 검토는 진행할 수 있다. SYS-02 전체 승인과 실제 Tool 호환 승인은 별개이며 SYS-03을 자동으로 착수하지 않는다.

## 17. 근거 사용 범위

정식 원작의 장소·사건은 [자료 기준](reference/Source_Basis.md)의 S-01~S-04에서 가져왔다. 승인된 표현·파티·시간·종료·UI는 SYS-01과 UI 기준을 따른다. 권고 접근은 사용자의 채택을 반영하고, Tool 사양·최종 수치·미정 시스템 정책과 구분했다. 외부 연구나 특정 게임 내부 구현의 확인 결과를 추가한 문서가 아니다.


## 18. 이동·월드맵 UI 구체 배치 — 검토안

### 18.1 시각 방향과 공용 토큰

최신 공용 지침 Ver0.8.1의 절제된 면·선·선택 강조를 적용한다. 지도와 세계를 우선하고 UI의 금속 휘장·톱니·다층 프레임·큰 작품명은 사용하지 않는다. 지도 원본의 장식은 지도 아트에만 남긴다. 청색 계열의 어두운 약반투명 면, 밝은 문자, 선택에만 제한한 따뜻한 강조색을 사용한다.

| 항목 | 100% | 125% | 150% |
|---|---:|---:|---:|
| 일반 본문 | 28px | 35px | 42px |
| 보조 본문 | 22px | 27px | 33px |
| 주/취소 버튼 | 248×64px | 310×80px | 372×96px |
| 버튼 간격 | 16px | 16px | 16px |
| 화면 좌우 여백 | 64px | 64px | 64px |
| 화면 하단 행동 영역 | 하단 40px | 하단 40px | 하단 40px |
| 월드맵 우측 열 | 490px | 550px | 620px |
| 목록·상세 일반 메뉴 좌측 열 | 410px | 470px | 525px |
| 공용 확인창 | 1030×860px | 1180×920px | 1300×950px |

수치는 **본 HTML의 검토 프로필**이다. 승인된 최종 px 또는 참고 게임 실측값이 아니다. 기본 문자 `#F2EFE5`, 보조 `#B3BFC4`, 선택 `#DCC28A`, 일반 면 `rgba(16,25,35,.94)` 계열을 사용한다. 모서리는 주요 창 12px·버튼 8px, 경계 1px가 기본이다. 글자/아이콘에 패널 알파를 곱하지 않는다. 고대비에서는 불투명 어두운 면을 사용한다. 실제 대비 검토 범위는 검수 보고서를 따른다.

| MOV-UI-09 도착 | 잔여 구간 완료 | 지도 현재 도시 변경·도착 알림·현장 진입 | 자동 판매·자동 귀환·추가 보상 없음 |
| MOV-UI-10 설명·기록·문제 | 공개 정보·오류·도움말 | 같은 크기 프로필의 공용 상세창, 본문만 스크롤 | 닫기/취소 버튼 위치 유지, 원래 선택 복귀 |

현재 위치는 실제 상태에서 읽는다. 이동 중에는 출발/도착 도시의 상점에 있는 것처럼 표시하지 않는다. 필드의 실제 목적지를 가리키는 정보와 월드맵의 선택 목적지는 분리한다.

### 18.3 입력과 포커스

| 문맥 | 검토 입력 |
|---|---|
| 현장 보행 | WASD/방향키, Shift 걷기 |
| 상호작용 | E/Enter 또는 대상 표식 |
| 미해결 상태 상세 | 해당 상태가 있을 때 P 또는 상태 표식 |
| 지역 지도·월드맵 | 현장에서 M / Tab |
| 여정·메뉴·이전 | J / Esc |
| 월드맵 목적지 | 도시 표식·목록 클릭, 위/아래 방향키 |
| 지도 표시 이동 | 드래그 또는 Shift+방향키 |
| 확대/축소 | 휠, +/− 또는 지도 도구 |
| 목록·버튼 | Tab/Shift+Tab, Enter/Space |
| 검토 도구 | F2, Esc로 닫기 |

한 시점에 활성 입력 문맥은 하나다. 메뉴·확인창·검토 도구 중에는 보행 입력을 처리하지 않는다. 모달은 배경을 비활성화하고 포커스를 내부에서 순환한다. 확인을 누른 채 유지하거나 한글 조합 중 Enter를 눌러 새로운 선택이 자동 확정되지 않게 한다. 버튼의 불가 사유는 항상 읽을 수 있는 본문/상태 영역에서 제공한다.

실물 게임패드·입력 재지정은 미구현/미검수다. 표시된 키는 이 HTML의 시험 프로필이며 엔진의 최종 매핑을 확정하지 않는다.

### 18.4 파일·자료와 시험 범위

HTML은 지도 PNG를 내부에 담고, 실행 시 Blob URL을 한 번 생성해 공유한다. 지도 그림의 원본 바이트는 바꾸지 않으며, 지명·버튼·노선·숫자는 실제 DOM/SVG 요소다. 이미지 시안을 통째로 깔고 보이지 않는 버튼만 덧씌우는 방식이 아니다. 외부 라이브러리·폰트·이미지 요청 없이 작동하도록 구성한다. 폰트 파일은 배포하지 않는다.

지도상 도시 위치·도시 임시명·노선·길이·2,400 G·화물 18·마차 수송량 40·소요일·운임·하루 정차는 `MOV-WORLDMAP-03` 검토 데이터다. 초기 보유 수단과 출발 확정 시 지출 정책도 시험 프로필이며 실제 경제 승인값이 아니다. 시나리오상 위치·관계·파티 8명 한도와 시연 데이터를 혼동하지 않는다.

필드 배경은 기존 동선을 유지하는 자체 간이 투영/충돌 표현이다. 최종 Map Tool 출력·Godot 3D 물리·조명·픽셀 아트 품질의 결과가 아니다. 차량 구매·개조, 실제 전투·퀘스트·채무 기한·다중 파티 경제는 이번 실행 범위 밖이다.

F2 검토 도구의 장면 변경은 테스트 상태 초기화다. 게임의 빠른 이동 기능이 아니며 정식 UI에 포함하지 않는다. 저장은 HTML 시험 상태이며, 저장소가 차단되면 해당 탭의 임시 저장임을 알린다.

### 18.5 검토 동선

**월드맵 도시 선택 → 경로·이동수단 비교 → 출발 준비 → 취소/출발 확정 → 여정 진행 → 정차 현장 확인 → 재개 → 목적지 도착**을 우선 확인한다. 지도 확대·패닝, 미개방 노선·미보유 수단·과적·거점 밖 출발, 보고 재열람, 큰 글씨에서의 목록/상세 접근도 함께 검토한다.

현장에서는 **안내판 → 지역 지도 → 공방 직접 출입·조사 → 중앙역 → 월드맵** 흐름을 유지한다. SYS-02 최종 승인 전 SYS-03 상세 제작으로 넘어가지 않는다.
